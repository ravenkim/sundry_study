## 3. AI API 설계 변경 (5/23~24)

**결정**: 기존 2·3단계(ON/OFF 판별 + 절약량 계산)를 **`POST /analyze` 단일 응답**으로 통합.

**요청** (BE → Cloud Run): `multipart` — `file`(이미지) + `metadata`(JSON)

| metadata 필드 | 설명 |
|---------------|------|
| 운영시간 | 요일별 켜는/꺼야 하는 시간 (`operatingSchedules`) |
| 자원 수량 | 에어컨·형광등·LED 대수 |

**응답** (AI → BE):

```json
{
  "result": "WASTE_DETECTED",
  "message": "Energy waste detected!",
  "ac_status": "OFF",
  "light_status": "ON",
  "reason": "...",
  "expected": "494원",
  "expectedKwh": "3.8 kWh"
}
```

- `expected`: **예상 절약 금액(원화 문자열)** — Gemini가 metadata + ON/OFF 기반 산출
- `expectedKwh`: **예상 절약 전기량** — FE「내 건물 절약 전기」집계용
- BE `SavingsCalculationService`는 제보 플로우에서 **미사용**(검증·Phase 2 참고용)
- AI 구현 담당: **이은총** (`ai/for_deploy/campus_api/main.py`)

## 4. 회원·소속 로직 정정 (5/24)

**초기 논의**: 회원가입 시 **건물(소속 건물)** 선택  
**최종 결정**: 회원가입은 **소속(Affiliation, 학교·캠퍼스)만** 선택 — 건물·강의실은 **제보 시** 선택

| 시점 | 선택 대상 | API·엔티티 |
|------|-----------|------------|
| 회원가입 | `Affiliation` (예: 삼육대학교) | `POST /register` body `affiliation` |
| 제보 | `LocationNode` LEAF (건물·강의실) | `POST /api/reports` `locationId` |
| 관리자(선택) | 담당 GROUP 노드 | `Member.locationNode`, `UserType.ADMIN` |

- OAuth(Google): 가입 전 `/signup/affiliation`에서 소속 선택 → 로그인 후 `PATCH /api/me/affiliation`
- **카카오 OAuth**: 해커톤 범위에서 **제외** — Google + 이메일만 유지 (코드·env 정리 완료)
