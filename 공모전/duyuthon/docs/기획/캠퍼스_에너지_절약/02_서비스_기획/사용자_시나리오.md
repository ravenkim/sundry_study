# 사용자 시나리오 (User Scenario)

---

## 시나리오 1 — 학생 제보 (Happy Path)

**페르소나**: 김민준 (22세, 공과대학 3학년, 점심 후 자주 도서관 가는 루트)

```
상황: 수업이 끝난 오후 2시, 강의실을 나오다 다음 강의가 5시인
      303호에 형광등 3개와 에어컨이 켜진 것을 발견.
```

| 단계 | 행동 | 시스템 반응 |
|------|------|------------|
| 1 | 앱 아이콘 탭 (잠금화면에서 바로 접근) | 메인 화면 로드 |
| 2 | "제보하기" 버튼 탭 | 카메라 실행 |
| 3 | 303호 방향 사진 촬영 (약 5초) | 업로드 중... |
| 4 | 건물명 "공학관 A동", 강의실 "303호" 선택 | — |
| 5 | "제출" 탭 | AI 분석 시작 (약 3~5초) |
| 6 | — | "조명 켜짐 확인! +50 포인트 적립" 화면 표시 |
| 7 | 포인트 탭으로 이동 | 누적 포인트 450P 표시 |

**총 소요 시간**: 약 30~40초

## 시나리오 2 — 관리자 대응

**페르소나**: 박시설 (45세, 공학관 시설팀 담당자)

```
상황: 오후 2시, 관리자 대시보드에 "공학관 A동 303호 조명 낭비 제보" 알림 수신.
```

| 단계 | 행동 | 시스템 반응 |
|------|------|------------|
| 1 | 대시보드 알림 확인 | 제보 사진 + AI 판별 결과 표시 |
| 2 | 시간표 확인 탭 | "303호 다음 수업: 오후 5시" 표시 → 빈 강의실 확인됨 |
| 3 | 제보 수리 처리 클릭 | 처리 완료 상태로 변경, 제보자 포인트 확정 |
| 4 | 월말 대시보드 확인 | 이번 달 절약 추정액 32만 원 표시, 정산 대기 6.4만 원 표시 |

## 시나리오 3 — 어뷰징 시도 (Edge Case)

**페르소나**: 이꼼수 (20세, 포인트 목적으로 조명을 켜고 찍으려 함)

| 단계 | 행동 | 시스템 반응 (레이어) |
|------|------|---------------------|
| 0 | 수업 중인 강의실에서 시도 | **[L1]** 운영 시간 중 → "운영 시간이 끝난 후 다시 시도" 반려 ✅ |
| 1 | 운영 종료 후 조명을 직접 켜고 촬영 | — |
| 2 | 제출 | **[L2]** AI: "조명 켜짐" → WASTE_DETECTED (누가 켰는지는 판별 불가) |
| 3 | 포인트 수령 | **[L3]** MVP: 즉시 적립 ✅ / P1: 24~48h 보류 → 시설팀 확인 후 확정 ⏳ |
| 4 | 같은 강의실 10분 뒤 재제보 | **[L1]** "이미 제보한 강의실" 반려 ✅ |
| 5 | 다른 강의실로 이동해 반복 (5건/30분) | **[L1]** 일 20건 캡 ⏳ / **[L4]** 이상 패턴 알림 → 검토 큐 ⏳ |
| 6 | 시설팀이 「원래 꺼져 있었음」 확인 | **[L4]** 관리자 이의 신청 → 포인트 회수 + 계정 경고 ⏳ |

> **한계 인정**: 1회성 「켜고 찍기」는 사진 AI만으로 완전 차단 불가 — **잔여 리스크로 수용**.  
> **보완**: L1(운영시간·1인1회·일일 캡) + L3(지연 지급·낮은 단가) + L4(이의·회수)로 **악용 이득 < 전기료·제재**.  
> 상세: [어뷰징_방지_제도.md](../05_운영_계획/어뷰징_방지_제도.md)

## 시나리오 4 — 포인트 교환

**페르소나**: 김민준 (누적 포인트 500P 달성)

| 단계 | 행동 | 시스템 반응 |
|------|------|------------|
| 1 | 포인트 탭 → "교환하기" 탭 | 교환 가능 리워드 목록 표시 |
| 2 | "스타벅스 아메리카노 (500P)" 선택 | 확인 팝업 |
| 3 | "교환" 확인 | "기프티콘이 카카오톡으로 발송되었습니다" |
