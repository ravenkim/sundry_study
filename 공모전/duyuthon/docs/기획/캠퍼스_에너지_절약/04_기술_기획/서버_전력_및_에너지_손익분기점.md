## 2. 플랫폼 전력 소비 추정

### 2.1 산출 방법

물리 서버는 **EcoReport 전용**으로 가동한다고 가정하고, 다음 요소를 합산한다.

1. **고정(Always-on)**: `ubuntu03` 24시간 Docker 3종 상시 실행
2. **변동(On-demand)**: 제보 1건당 Cloud Run 추론 + Gemini API 호출

산출식:

```
월간 kWh = (평균 소비전력 W × 720h) / 1,000          … 물리 서버
제보 1건 Wh = Cloud Run( vCPU·RAM 초 ) + Gemini( Wh/프롬프트 ) … CCF·Google 공식값
```

캠퍼스 **절약 전력** 상수·요금·탄소계수 근거는 [절약량_환산_공식_및_근거.md](./절약량_환산_공식_및_근거.md)와 동일 계열을 따른다.

## 4. 에너지 손익분기점 (Energy BEP)

**정의**: 한 달 동안 플랫폼 소비 전력 ≤ 캠퍼스 절약 전력이 되는 시점.

```
순절약 kWh = (월 제보 건수 × 유효 절약 kWh/건) − (40 + 제보 건수 × 0.0005)
```

### 4.1 손익분기 제보 건수

고정분 **40 kWh**, 변동 **0.0005 kWh/건** (§2.3), 유효 절약 **E** kWh/건:

```
R × E = 40 + 0.0005R  →  R = 40 / (E − 0.0005)
```

| 유효 절약 E (kWh/건) | BEP 제보 건수/월 | 일평균 (22 영업일) | 대비: 플랫폼 1건 절약 |
|---------------------|-----------------|-------------------|---------------------|
| 3.8 (복합·100% 조치) | **11건** | **0.5건/일** | **~950×** (3.8 vs 0.0004 kWh) |
| 2.55 (가중평균·100%) | **16건** | **0.7건/일** | **~6,400×** |
| 1.79 (가중평균·70% 조치) | **22건** | **1.0건/일** | **~4,500×** |
| 1.28 (가중평균·50% 조치) | **31건** | **1.4건/일** | **~3,200×** |
| 0.8 (조명만·100%) | **50건** | **2.3건/일** | **~2,000×** |

**MVP 기준값 (권장)**: 유효 **1.79 kWh/건** → **월 22건**, **하루 1건**이면 플랫폼 전력을 상쇄.

### 4.2 캠퍼스 규모로 환산

[수익_구조.md](../03_비즈니스_모델/수익_구조.md) 가정 — 건물 1개, 강의실 50, **일 10개소** 낭비:

| 지표 | 값 |
|------|-----|
| 잠재 낭비 이벤트 | 10 × 22 = **220건/월** |
| 제보율 10% | 22건/월 제보 → **Energy BEP 도달** |
| 제보율 20% | 44건/월 → 순절약 **약 34 kWh/월** (플랫폼 대비 **약 1.8배**) |

```
순절약 (44건, 70% 조치): 44 × 1.79 − 40.5 ≈ 38 kWh/월
연간: ≈ 450 kWh, CO₂ ≈ 207 kg (0.4594 계수)
```

### 4.3 손익분기 타임라인 (파일럿 목표 대비)

| 단계 | 목표 (06_기대효과) | 제보/월 | Energy BEP 대비 |
|------|-------------------|---------|-----------------|
| 파일럿 1개월 | 500건 (전 캠퍼스) | 500 | BEP의 **23배** — 순절약 **~855 kWh/월** |
| 건물 1개만 (제보율 10%) | — | 22 | **BEP** |
| 초기 성장 3개월 | 5,000건 | 5,000 | 순절약 **~8,900 kWh/월** |

> **500건/월**은 “캠퍼스 전체” 목표이므로, **건물 1~3개 파일럿**만으로도 Energy BEP(월 ~22건)는 **출시 첫 달**에 충분히 달성 가능하다.

### 4.4 재무 BEP vs Energy BEP

| 구분 | BEP 조건 | 에코리포트 기준 |
|------|----------|----------------|
| **Energy BEP** | 절약 전력 ≥ 플랫폼 전력 | **월 ~22건** (가중·70% 조치) |
| **재무 BEP** | 플랫폼 수수료 ≥ API·클라우드 **현금** 지출 | **~32개 건물** ([수익_구조.md §3](../03_비즈니스_모델/수익_구조.md)) |

에너지 관점에서는 **하루 1건** 수준의 실효 제보로 탄소·전력 순효익이 플러스로 전환되며, 재무 BEP보다 **3~4 orders of magnitude 낮은 참여**로 달성된다. “에너지 절약 플랫폼”으로서의 정당성은 초기 파일럿 단계에서 이미 확보된다.
