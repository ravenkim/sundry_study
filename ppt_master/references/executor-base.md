# 실행자 공통 지침

> 스타일별 내용은 해당 `executor-{스타일}.md`에 있습니다. 기술 제약은 shared-standards.md입니다.

---

## 1. 템플릿 준수 규칙

프로젝트 `templates/`에 템플릿이 있으면 구조를 따라야 합니다.

| 페이지 유형 | 대응 템플릿 | 준수 규칙 |
|-----------|----------------------|-----------------|
| 표지 | `01_cover.svg` | 배경·장식·구조 상속; 플레이스홀더만 실제 내용으로 교체 |
| 챕터 | `02_chapter.svg` | 번호 스타일·제목 위치·장식 상속 |
| 본문 | `03_content.svg` | 헤더/푸터 스타일 상속; **본문 영역은 자유 배치** |
| 맺음 | `04_ending.svg` | 배경·감사 문구 위치·연락처 레이아웃 상속 |
| 목차 | `02_toc.svg` | **선택**: 목차 제목·목록 스타일 상속 |

### 페이지-템플릿 매핑 선언(필수 출력)

각 페이지 생성 전 사용 템플릿(또는 "자유 설계")을 명시합니다.

```
📝 **템플릿 매핑**: `templates/01_cover.svg` (또는 "없음(자유 설계)")
🎯 **준수/전략**: [구체적 설명]
```

- **본문 페이지**: 템플릿은 헤더·푸터만 정의; 본문 영역은 실행자가 자유 배치
- **템플릿 없음**: 설계 명세·콘텐츠 개요만으로 전면 생성

## 2. 디자인 파라미터 확인(필수 단계)

> 첫 SVG 전에 **설계 명세·콘텐츠 개요**의 핵심 디자인 파라미터를 검토·출력해 이후 생성이 명세와 일치하도록 합니다.

출력에 포함: 캔버스 치수, 본문 글자 크기, 색(주/보/포인트 HEX), 글꼴 계획.

**필수 이유**: "명세와 실행 불일치"를 방지합니다.

---

## 3. 실행 지침

- **근접성**: 관련 요소를 가까이 묶어 시각적 그룹 형성; 무관 그룹은 간격으로 분리
- **명세 엄수**: 색·레이아웃·캔버스·타이포를 명세대로
- **템플릿 구조**: 있으면 시각적 골격 상속
- **메인 에이전트 소유**: SVG는 공통 맥락·페이지 간 연속성 때문에 현재 메인 에이전트가 수행
- **생성 리듬**: 전역 디자인 맥락 확정 후 **한 페이지씩** 같은 연속 맥락에서 생성; 예: 5장 묶음 배치 금지
- **단계적 배치 생성(권장)**:
  1. **시각 구축**: 모든 SVG를 순서대로 연속 생성해 스타일·좌표 일관성 확보
  2. **논리 구축**: SVG 확정 후 발표 노트를 일괄 생성해 내러티브 연속성 확보
- **기술 사양**: SVG 제약·PPT 호환은 [shared-standards.md](shared-standards.md)
- **시각적 깊이**: shared-standards.md의 필터 그림자·글로우·그라데이션 채우기·점선 스트로크·그라데이션 오버레이로 층위 표현 — 평면만이면 미완성으로 보임

### SVG 파일 명명

형식: `<번호>_<페이지명>.svg`

- **한글 콘텐츠** → 한글 파일명: `01_표지.svg`, `02_목차.svg`
- **라틴/영문 콘텐츠** → 영문 파일명: `01_cover.svg`, `02_agenda.svg`
- **번호**: 두 자리, 01부터
- **페이지명**: 짧고 설명적이며 설계 명세·개요의 제목과 대응

## 4. 아이콘 사용

네 가지: **A: 이모지** (`<text>🚀</text>`) | **B: AI 생성**(기본 도형 SVG) | **C: 내장 라이브러리**(`templates/icons/` 6700+, 권장) | **D: 사용자 지정**

**내장 아이콘 — 플레이스홀더(권장)**:

```xml
<!-- chunk (기본 — 직선 기하, 각진 구조) -->
<use data-icon="chunk/home" x="100" y="200" width="48" height="48" fill="#005587"/>

<!-- tabler-filled (베지어 윤곽, 부드러운 형태) -->
<use data-icon="tabler-filled/home" x="100" y="200" width="48" height="48" fill="#005587"/>

<!-- tabler-outline (얇은 선형 — 화면용 라이트 톤) -->
<use data-icon="tabler-outline/home" x="100" y="200" width="48" height="48" fill="#005587"/>
```

> `embed_icons.py`를 수동 실행할 필요 없음 — `finalize_svg.py`가 삽입합니다.

**세 라이브러리**:

| 라이브러리 | 스타일 | 개수 | 접두사 | 사용 시점 |
|---------|-------|-------|--------|-------------|
| `chunk` | 채움·직선 기하 | 640 | `chunk/` | 기본 — 대부분 |
| `tabler-filled` | 채움·베지어 | 1000+ | `tabler-filled/` | 부드러운 유기적 형태 |
| `tabler-outline` | 선/스트로크 | 5000+ | `tabler-outline/` | 화면용 가벼운 미학 |

> 한 프레젠테이션 = **하나의 라이브러리만**. 혼합 금지. 없는 아이콘은 **같은 라이브러리**에서 대안.

**검색** — 터미널, 토큰 비용 없음:
```bash
ls skills/ppt-master/templates/icons/chunk/ | grep home
ls skills/ppt-master/templates/icons/tabler-filled/ | grep home
ls skills/ppt-master/templates/icons/tabler-outline/ | grep chart
```

**추상 개념 → 아이콘명**(`chunk` 기준; tabler는 `ls | grep`으로 확인):

| 개념 | chunk | tabler-filled / tabler-outline |
|---------|-------|-------------------------------|
| 성장 | `arrow-trend-up` | 동일 |
| 하락 | `arrow-trend-down` | 동일 |
| 성공·완료 | `circle-checkmark` | `circle-check` |
| 경고·위험 | `triangle-exclamation` | `alert-triangle` |
| 혁신·아이디어 | `lightbulb` | `bulb` |
| 전략·목표 | `target` | 동일 |
| 효율·속도 | `bolt` | 동일 |
| 협업·팀 | `users` | 동일 |
| 설정 | `cog` | `settings` |
| 보안·신뢰 | `shield` | 동일 |
| 금융 | `dollar` | `currency-dollar` |
| 시간 | `clock` | 동일 |
| 위치 | `map-pin` | 동일 |
| 커뮤니케이션 | `comment` | `message` |
| 분석·데이터 | `chart-bar` | 동일 |
| 프로세스 | `arrows-rotate-clockwise` | `refresh` |
| 글로벌 | `globe` | `world` |
| 우수·수상 | `star` | 동일 |
| 확장 | `maximize` | 동일 |
| 문제 | `bug` | 동일 |

> 이름이 자명한 경우(home, user, file 등) 표 없이 `grep`만으로 충분.

> **검증**: 설계 명세에 아이콘 목록이 있으면 실행자는 **그 목록만** 사용. 사용 전 `ls | grep`으로 존재 확인. **라이브러리 혼합 금지**.

## 5. 시각화 참조

설계 명세에 **VII. 시각화 참조 목록**이 있으면 해당 유형 페이지를 그리기 전에 `templates/charts/`의 참조 SVG를 읽습니다. 경로명 `templates/charts/`는 하위 호환을 위해 유지합니다.

🚧 **관문 — 최초 사용 전 필수**: VII에 적힌 시각화 유형을 **처음** 만날 때, 해당 페이지 생성 **전에** `read_file templates/charts/<이름>.svg`를 **반드시** 수행합니다. 레이아웃 좌표·카드 리듬·간격을 **참고·영감**으로만 쓰고 엄격 복제는 아닙니다. 프로젝트 색·타이포·내용으로 독자 디자인합니다.

> **워크플로**: 템플릿 SVG 읽기 → 구조·간격 이해 → 참고해 원본 SVG 설계 → 템플릿 그대로 복제 금지
> **재사용**: 같은 유형은 한 번 이해한 뒤 반복 읽기 불필요
> **변경**: 유형이 바뀌거나 구조를 다시 볼 필요가 있을 때만 재읽기

**적응 규칙**:
- **유지**: 설계 명세에 명시된 시각화 유형(막대·선·원·타임라인 등)
- **맞춤**: 수치·라벨·색(프로젝트 팔레트)·치수를 페이지에 맞게
- **자유 조정**: 구도·축·그리드·범례·간격·장식 — 정확하고 읽기 쉬우면 창의적 변주 허용
- **금지**: 명세 없이 유형 변경, 개요에 있는 데이터·구조 요소 누락

> 시각화 템플릿: `templates/charts/`(52종). 색인: `templates/charts/charts_index.json`

## 8. 발표 노트 생성 틀

### 작업 1. 통합 발표 노트 문서

**모든 SVG 페이지 생성·확정 후** "논리 구축 단계"로 `notes/total.md`를 작성합니다.

**페이지별로 바로 쓰지 않는 이유**: 한 번에 쓰면 전환·스크립트 흐름을 설계하기 쉬움.

**형식**: 각 페이지는 `# <번호>_<페이지제목>`으로 시작, 페이지 사이는 `---`. 각 페이지: 스크립트 본문(2~5문장), `핵심 포인트: ① ② ③`, `소요 시간: X분`. 첫 페이지 제외하고 본문은 `[전환]` 구문으로 시작.

**공통 연출 마커**(모든 스타일 공통):

| 마커 | 용도 |
|--------|---------|
| `[멈춤]` | 중요 내용 후 숨 고르기 |
| `[전환]` | 각 페이지 텍스트 맨 앞, 이전 페이지에서 이어 붙이기 |

> 스타일별 확장 마커는 `executor-{스타일}.md` 참고.

**언어 일관성**: 발표 노트의 구조 레이블·연출 마커는 **발표 콘텐츠 언어와 동일**하게 현지화합니다. 한국어 발표면 예: `[전환]`, `핵심 포인트:`, `소요 시간:` 등 — 영어 레이블과 비한국어 본문을 섞지 않습니다.

다른 언어면 그 언어의 자연스러운 표현으로 레이블을 번역합니다.

**요구사항**:

- 대화체로 자연스럽게
- 페이지 핵심·발표 포인트 강조
- 사용자는 `notes/`에서 수동 편집 가능

### 작업 2. 페이지별 파일로 분할

`notes/total.md`를 `notes/` 아래 페이지별 파일로 나눕니다(후처리 스크립트).

**파일 명명**:

- **권장**: SVG명과 일치(`01_cover.svg` → `notes/01_cover.md`)
- **호환**: `slide01.md` 형식도 지원

## 9. 완료 후 다음 단계

> **자동 연속**: 시각 구축(SVG 전부)·논리 구축(노트 전부) 후 실행자는 곧바로 후처리 파이프라인으로 이어갑니다.

**후처리·내보내기**([shared-standards.md](shared-standards.md)):

```bash
# 1. 발표 노트 분할
python3 scripts/total_md_split.py <프로젝트경로>

# 2. SVG 후처리(아이콘·이미지 등)
python3 scripts/finalize_svg.py <프로젝트경로>

# 3. PPTX 내보내기
python3 scripts/svg_to_pptx.py <프로젝트경로> -s final
# 출력: exports/<프로젝트명>_<타임스탬프>.pptx + exports/<프로젝트명>_<타임스탬프>_svg.pptx
```
