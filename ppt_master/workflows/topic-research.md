# 주제 조사 워크플로

> **독립 전처리 워크플로** — 메인 PPT 파이프라인 입력으로 쓰거나 단독으로 쓸 수 있습니다.

## 발동 조건

사용자가 **주제명·짧은 설명·요구사항만** 제공하고 PDF·DOCX·URL 등 상세 원본 파일은 없을 때.

예:
- "○○에 대한 PPT를 만들어 줘"
- "재생에너지 동향 프레젠테이션"
- "신제품 소개(짧은 설명만 있음)"

## 산출물

모든 출력은 `projects/` 아래에 둡니다.

| 산출물 | 경로 | 예 |
|-------------|------|---------|
| 구조화 Markdown | `projects/<주제명>.md` | `projects/joe_hisaishi.md` |
| 이미지 폴더 | `projects/<주제명>/` (확장자 없는 문서명과 동일) | `projects/joe_hisaishi/` |

> **이름 규칙**: Markdown 파일명(`.md` 제외)과 이미지 폴더명은 **동일**해야 합니다.
>
> **출력 위치**: 문서와 이미지 폴더 모두 `projects/` 안에만 둡니다. 저장소 루트 등 다른 곳에 두지 않습니다.

## 과정 개요

```
주제 확인 → 내용 조사 → 이미지 수집 → 산출
```

---

## 1단계: 주제 확인

⛔ **차단**: 조사 시작 전 사용자와 아래를 확인합니다. 초기 메시지에 이미 분명히 담겼으면 확인을 건너뜁니다.

| 항목 | 설명 | 예 |
|------|-------------|---------|
| **주제** | 핵심 주제 | 인물·기술·회사 등 |
| **범위·초점** | 다룰 측면 | 약력·작품·수상 등 |
| **깊이** | 개요 vs 심층 | 일반 독자 수준 등 |
| **언어** | 출력 언어 | 사용자가 원하는 언어 |

**요청이 이미 충분히 명확하면**(예: "○○에 대한 PPT") 합리적 기본값을 두고 과도한 질문은 하지 않습니다.

## 2단계: 내용 조사

### 2.1 정보 수집

`WebSearch`와 `WebFetch`로 여러 출처를 활용합니다.

| 출처 유형 | 우선순위 | 도구 | 비고 |
|------------|----------|-------|-------|
| 백과·개요 | 높음 | WebSearch → WebFetch | 개요·연표·핵심 사실 |
| 공식 사이트 | 높음 | WebFetch | 1차 정보 |
| 뉴스·기사 | 중간 | WebSearch → WebFetch | 최근 이슈·평가 |
| 전문 DB | 낮음 | WebSearch | 업종별 데이터 |

**전략**:
1. 넓은 WebSearch로 지형 파악
2. 권위 페이지 2~3개를 WebFetch로 정독
3. 필요 시 하위 주제별 추가 검색

### 2.2 내용 구성

수집 정보를 아래 뼈대로 Markdown에 정리합니다.

```markdown
# <주제명>

> 주제 한 줄 요약.

## 개요
[2~3문단 요약]

## 배경·역사
[연표·기원·이정표]

## 핵심 측면
### 측면 1: [...]
### 측면 2: [...]
### 측면 3: [...]

## 성과·영향
[수상·인지도·파급]

## 핵심 수치
| 항목 | 값 |
|------|-------|
| ... | ... |

## 출처
- [제목](URL)
```

> 뼈대는 **참고용**이며 주제에 맞게 섹션을 조정합니다.

**콘텐츠 지침**:
- 날짜·이름·수치 등 구체적 사실 포함 — 막연한 일반론 지양
- 인용문은 가능하면 보존
- 검증을 위해 데이터 출처 표기
- PPT에 맞는 밀도: 슬라이드 10~15장 분량은 되되 논문 수준 과잉은 피함

### 2.3 문서 저장

`projects/`에 저장:

```
projects/<주제명>.md
```

## 3단계: 이미지 수집

### 3.1 이미지 출처 전략

**공개·자유 이용 가능** 이미지를 아래 순으로 탐색합니다.

| 출처 | 찾는 방법 | 라이선스 |
|--------|------------|-------|
| **위키미디어** | 위키 페이지 WebFetch → `upload.wikimedia.org` URL — `/thumb/`·크기 접미사 제거해 원본 | CC-BY-SA·퍼블릭 도메인 등 |
| **공식 사이트** | 갤러리·보도 자료 | 편집·교육 목적 등 조건 확인 |
| **정부·기관** | 공식 자료·갤러리 검색 | 종종 퍼블릭 도메인 |
| **CC 검색** | `site:commons.wikimedia.org` 등 | 라이선스별 확인 |

**피할 것**: 워터마크 스톡, 상업적 저작권 불명, 라이선스 불명 소셜 업로드.

### 3.2 선정 기준

| 기준 | 지침 |
|-----------|--------|
| **수량** | 6~12장(슬라이드 10~15장 지원) |
| **다양성** | 인물·장면·로고·행사 사진 등 주제에 맞게 |
| **해상도** | 가로 1000px 이상 선호; 썸네일 지양 |
| **관련성** | 표지·삽화·배경 등 역할이 분명할 것 |
| **비율** | 배경용 가로·프로필용 세로 등 혼합 |

### 3.3 다운로드

```bash
mkdir -p "projects/<주제명>"

curl -L -o "projects/<주제명>/설명적_이름.jpg" "<image_url>"
```

**파일명 규칙**:
- 의미 있는 영문·라틴 파일명: `subject_event_2023.jpg` — `image1.jpg` 지양
- 소문자·공백은 밑줄
- 주제·맥락 포함

### 3.4 고해상도 URL 패턴

| 출원 | 썸네일 URL | 원본 URL |
|--------|--------------|---------------|
| 위키미디어 | `.../thumb/.../250px-...` | `thumb/`와 크기 접미사 제거한 경로 |

## 4단계: 산출 요약

2·3단계 후 짧은 요약을 출력합니다.

```markdown
## 주제 조사 완료

**주제**: <주제명>
**문서**: `projects/<주제명>.md` — [섹션 수, 대략 ○○자]
**이미지**: `projects/<주제명>/` — [N장]

| 파일명 | 출처 | 설명 |
|----------|--------|-------------|
| ... | ... | ... |
```

> 이후 `project_manager.py import-sources`로 넣거나 파일을 직접 읽어 PPT 생성에 씁니다.

---

## 참고

- 이 워크플로는 **자료 수집만** 수행 — PPT 프로젝트·SVG·설계 명세는 만들지 않음
- Markdown은 **PPT 준비형**: 슬라이드로 자연스럽게 나뉘는 구조·사실 위주
- **출처** 섹션은 필수 — 출처 표기·검증용
- 유명 주제는 WebSearch·WebFetch 2~3 라운드로 보통 충분; 과잉 조사 지양
- 틈새 주제는 더 넓게 검색 — 판단에 따름
