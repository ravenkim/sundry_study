## 03. 문제 정의 ✅

> **발표 시간**: 60초 | **필수/선택**: 필수

### 슬라이드 본문

**목표**: "왜 지금, 왜 학생인가" 공감 — 아래 2~3개만 선택

- **현상**: 수업이 끝난 뒤에도 조명·에어컨이 켜진 채 방치 — **보이지 않는 낭비**
- **규모 (택1)**:
  - 교내 에너지 비용의 약 **30%**가 빈 공간 낭비
  - 100개 강의실 기준 월 **10만 원+** 불필요 지출 (836 kWh, 130원/kWh)
- **기존 해결 방안의 한계**:

| 기존 방안 | 한계 |
|----------|------|
| IoT 스마트빌딩 | 수억 원·장기 투자, 기존 건물 적용 어려움 |
| 관리인 순찰 | 인건비·지연·야간·주말 공백 |
| 캠페인·스티커·방송 | 보상 없음·일시적·행동 전환율 낮음 |

- **핵심 가설**: 합리적 보상 → 학생 **자발적 제보**
  - 검증 사례: 씨리얼(영수증 리워드), 우리동네 환경지킴이(시민 제보 → 지역화폐)
- **(선택) 정책 맥락**: 2030 탄소중립 · 교육부 그린스마트 미래학교 · 전기료 상승

### 시각 자료

- **Before vs Pain** 2분할: 빈 강의실 + 켜진 조명 | 비용·탄소 아이콘
- 숫자는 **1~2개만** 크게 (30% 또는 10만 원+)

### 발표 멘트

> "마지막으로 나가는 사람은 학생인데, 꺼도 보상이 없어서 대부분 그냥 지나갑니다."

## 04. 솔루션 ✅

> **발표 시간**: 45초 | **필수/선택**: 필수

### 슬라이드 본문

**목표**: 우리 접근이 IoT 대안임을 각인

- **3축**: 크라우드소싱 + AI + 포인트 보상
- **차별점**: 설비 투자 없음 · 즉시 도입 · 학생 참여 동기(포인트·기프티콘)

**포지셔닝 (저비용 ↔ 고비용)**:

```
              저비용 ◄──────────────────────► 고비용
                  │                              │
          [에코리포트]                  [IoT 스마트빌딩]
       (크라우드소싱 기반)              (인프라 구축 필요)
           학생 자발 참여                   자동화 완성
          즉시 도입 가능                  장기 투자 필요
```

**선순환 구조**:

```
학생 제보 → AI 판별 → 포인트 → 관리자 조치 → 절약량 → 포인트 풀 재순환
```

- **3단계 AI** (이름만, 상세는 05·06에서):
  1. YOLOv8n — 사람·가구 감지
  2. YOLOv8n Custom — 에어컨 탐지
  3. Gemini 2.5 Flash — 조명·에어컨 ON/OFF 판별

### 시각 자료

- 선순환 다이어그램 1장 (원형 또는 가로 플로우)
- IoT vs 에코리포트 2열 비교 (위 텍스트 박스)

### 발표 멘트

> "수억 원 IoT 대신, 이미 있는 스마트폰과 AI로 낭비를 찾고, 절약분 일부를 학생에게 돌려줍니다."

## 05. 핵심 기능 ✅

> **발표 시간**: 60초 | **필수/선택**: 필수

### 슬라이드 본문

| 기능 | 설명 | MVP 상태 |
|------|------|----------|
| **AI 이미지 분석** | 3단계 파이프라인, 5초 이내 판별 | BE Cloud Run `/analyze` 연동 ✅ / FE mock UX |
| **제보·포인트** | 사진 + 건물/강의실 → AI 판별 후 저장 | `POST /api/reports` + AI ✅ / 포인트 mock |
| **관리자 대시보드** | 제보 목록·월 절약 요약 | UI 6화면 ✅ / mock 데이터 |

**AI 3단계 상세 (슬라이드 각주 또는 보조 슬라이드)**:

| 단계 | 모델 | 역할 |
|------|------|------|
| 1 | YOLOv8n (COCO) | person/chair/desk → 빈 강의실·사용 중 여부 |
| 2 | YOLOv8n Custom (`ac_best.pt`, mAP 0.990) | 천장 4-way 에어컨 탐지·크롭 |
| 3 | Gemini 2.5 Flash (Vertex AI) | 조명·에어컨 ON/OFF JSON → WASTE_DETECTED / PASS |

- **1단계**: chair=0 AND desk=0 → 강의실 아님 / person≥1 → 사용 중 / person=0 → 2단계
- **3단계**: ac_status=ON 또는 light_status=ON → **낭비 확인**

**학생 UI (5탭)**: 홈 · 낭비 제보 · 제보 이력 · 포인트샵 · 마이페이지  
**관리자 UI (6화면)**: 대시보드 · 제보 · 건물 · 포인트 · 통계 · 사용자

### 시각 자료

- FE 스크린샷 **4장 필수**: 홈 · 제보 작성 · AI 결과 · 포인트/포인트샵
- AI 3단계 진행 UI (mock 시뮬레이터) 캡처 1장

### 발표 멘트

> "학생은 사진 한 장만 올리면 AI가 5초 안에 낭비를 판별하고, 확인되면 바로 포인트가 쌓입니다."

## 06. 서비스 플로우 / 데모 ✅ ⭐

> **발표 시간**: 45초 (데모 포함 시 최대 105초) | **필수/선택**: 필수 — **가장 중요**

### 슬라이드 본문

#### A. 학생 플로우 (50~60초 데모)

```
로그인(이메일) → 홈 → 제보(사진 + 건물/강의실) → AI 3단계 UI(mock) → 포인트 적립 → 이력·포인트샵
```

| 단계 | 화면 | 설명 |
|:----:|------|------|
| 1 | 로그인 | 이메일 회원가입/로그인 (BE 연동 ✅) |
| 2 | 홈 | 제보하기 CTA |
| 3 | 제보 작성 | 카메라/갤러리 + 건물·강의실 선택 |
| 4 | AI 분석 | 3단계 진행 UI → 낭비 확인 / 판별 불가 |
| 5 | 완료 | 포인트 적립 (+50~89P) |
| 6 | 이력·포인트샵 | 누적 포인트·교환 UI |

**시나리오 예** ([사용자_시나리오.md](../기획/캠퍼스_에너지_절약/02_서비스_기획/사용자_시나리오.md)):
- 공학관 A동 303호, 조명+에어컨 켜짐 → **+50~89P** (2시간 방치 기준 약 89P)
- 총 소요: 약 30~40초

#### B. 관리자·부가 (20~30초, 시간 없으면 생략)

- 관리자 대시보드: 제보 목록, 월 절약 요약 (**mock 데이터 명시**)
- 어뷰징: 동일 강의실 1시간 중복 차단 등 **설계만** 한 줄

#### C. 구현 범위 (필수 — 정직하게)

| 구분 | 해커톤 MVP |
|------|------------|
| ✅ **완료** | UI 6화면(학생+관리자), 이메일 회원가입/로그인, JWT, `POST/GET /api/reports`(Cloud Run AI), `GET /api/buildings`, `GET /api/points/me`, Docker 배포, monorepo `ai/` |
| 🔶 **데모** | FE AI 진행 UI mock, 포인트·관리자 — **FE mock** (`VITE_USE_MOCK`, 기본 `true`) |
| ⏳ **미구현** | GCS, `aiResult` DB, Kafka, 관리자 API |

### 시각 자료

- 유저 저니 플로우차트 (위 A 단계)
- **라이브 또는 녹화 데모** 영역 (30~60초 권장)
- 슬라이드 하단 각주: *"제보 AI 판별은 BE→Cloud Run 연동 완료, FE mock은 UX 시연용"*

### 데모 팁

- [ ] 사전에 로그인·제보 1건 **캐시** — 현장은 "제보 → AI 결과"만 보여도 됨
- [ ] mock임을 슬라이드 각주 또는 입으로 **1회만** 언급 (숨기지 말 것)
- [ ] 데모 URL·계정·네트워크 사전 확인

### 발표 멘트

> "제보 저장 시 Spring Boot가 Cloud Run AI를 호출해 낭비를 판별합니다. 화면의 AI 진행 UI는 mock으로 UX를 보여주고, 포인트·관리자는 mock 데이터입니다."

## 08. 기대효과 ✅

> **발표 시간**: 15초 (축약) | **필수/선택**: 필수

### 슬라이드 본문

**숫자 1~2개만**:

| 지표 | 100개 강의실 캠퍼스 기준 |
|------|--------------------------|
| 월 절약 전기 | **600~1,000 kWh** |
| 월 탄소 절감 | **280~470 kg CO₂** |
| 연간 효과 | 소나무 **50~80그루** 흡수량과 동등 |

- **확장**: 전국 대학 → 공공기관 · 오피스 · 아파트 공용부
- **사회적 가치**: 학생 주도 탄소중립 문화 · IoT 없는 스마트캠퍼스 대안

**(Q&A용, 슬라이드 노트에만)**:

- 건물주: 월 전기료 **10~30%** 절감 (설비 투자 없이)
- 플랫폼: 절감액 20% 중 **10%** 수수료, BEP **~32개 건물**

### 시각 자료

- 임팩트 숫자 1~2개 크게 (kWh 또는 CO₂)
- 확장 로드맵은 한 줄 텍스트 (시간 없으면 생략)

### 발표 멘트

> "100개 강의실만 해도 한 달에 수백 kWh, 전국 대학으로 확장하면 연간 수천만 원 규모 절감이 가능합니다."
