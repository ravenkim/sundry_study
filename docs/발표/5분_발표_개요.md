## 1. 5분 발표 핵심 원칙

| 원칙 | 설명 |
|------|------|
| **한 메시지** | "사진 한 장 → AI 판별 → 포인트 → 캠퍼스 전기료 절감"만 기억나게 |
| **문제 1분, 데모 2분** | 통계·배경은 압축, **실제 화면/플로우**에 시간 투자 |
| **목표 vs 현재 구분** | AI·Kafka·GCS는 **설계 완료**, 해커톤은 **UI + BE 일부 + mock AI 데모** — 과장 없이 명확히 |
| **숫자는 1~2개만** | 예: "강의실 낭비 약 30%" 또는 "100개 강의실 기준 월 10만 원+" 중 택1 |
| **마지막 15초** | 서비스명 + 한 줄 + 데모 URL/GitHub |

**피해야 할 것**: 기술 스택 나열 1분+, 팀원 이력 소개, 아키텍처 전체 설명, 슬라이드 15장 이상

## 3. 구간별 들어갈 내용 개요

### ① 오프닝 (30초) — 슬라이드 01

**목표**: 청중이 "무슨 서비스인지" 10초 안에 이해

- **에코리포트 (EcoReport)** — AI 기반 캠퍼스 에너지 낭비 제보·보상 플랫폼
- **14팀** · 김해준 · 차성호 · 이은총
- **한 줄**: 빈 강의실 전등/에어컨 사진 → AI 분석 → 포인트 적립
- (선택) 2030 탄소중립·캠퍼스 에너지 비용 맥락 한 마디

**멘트 예시**  
> "IoT 없이, 학생 스마트폰만으로 캠퍼스 전기 낭비를 줄이고 절약분을 학생에게 돌려주는 에코리포트입니다."

---

### ② 문제 정의 (60초) — 슬라이드 03

**목표**: "왜 지금, 왜 학생인가" 공감

| 포인트 | 내용 (택해서 2~3개) |
|--------|---------------------|
| 현상 | 수업 끝난 뒤에도 조명·에어컨이 켜진 채 방치 — **보이지 않는 낭비** |
| 규모 | 교내 에너지 비용의 약 **30%**가 빈 공간 낭비 (또는 100개 강의실 기준 월 **10만 원+** 불필요 지출) |
| 기존 한계 | IoT 스마트빌딩 = **고비용·장기**, 순찰 = **인건비·지연**, 캠페인 = **보상 없음** |
| 핵심 가설 | 합리적 보상이 있으면 학생이 **자발적으로 제보**한다 (씨리얼·환경지킴이 등 검증 사례 언급 가능) |

**시각 자료**: Before(빈 강의실 + 켜진 조명) vs Pain(비용·탄소) 간단 도식 1장

**멘트 예시**  
> "마지막으로 나가는 사람은 학생인데, 꺼도 보상이 없어서 대부분 그냥 지나갑니다."

---

### ③ 솔루션·차별점 (45초) — 슬라이드 04

**목표**: 우리 접근이 IoT 대안임을 각인

- **크라우드소싱 + AI + 포인트 보상** 3축
- **차별점**: 설비 투자 없음 · 즉시 도입 · 학생 참여 동기(포인트·기프티콘)
- **선순환 한 장** (말로 또는 다이어그램):

```
학생 제보 → AI 판별 → 포인트 → 관리자 조치 → 절약량 → 포인트 풀 재순환
```

- **3단계 AI** (이름만, 상세는 ④에서): YOLO(사람·가구) → YOLO(에어컨) → Gemini(ON/OFF)

**멘트 예시**  
> "수억 원 IoT 대신, 이미 있는 스마트폰과 AI로 낭비를 찾고, 절약분 일부를 학생에게 돌려줍니다."

---

### ④ 핵심 기능·데모 (105초) — 슬라이드 05~06 ⭐ 가장 중요

**목표**: 심사위원이 "실제로 돌아가는구나"를 느끼게 — **라이브 또는 녹화 30~60초 권장**

#### A. 학생 플로우 (50~60초)

1. 로그인(이메일) → 홈
2. **제보**: 사진 업로드 + 건물/강의실 선택
3. **AI 분석** (mock 시뮬레이터): 3단계 진행 UI → 낭비 확인 / 판별 불가
4. **포인트 적립** → 이력·포인트샵 화면 한 컷

#### B. 관리자·부가 (20~30초, 시간 없으면 생략)

- 관리자 대시보드: 제보 목록, 월 절약 요약 (mock 데이터 명시)
- 어뷰징: 동일 강의실 1시간 중복 차단 등 **설계만** 한 줄

#### C. 구현 범위 한 문장 (필수, 정직하게)

| 구분 | 해커톤 MVP |
|------|------------|
| ✅ 완료 | UI 6화면(학생+관리자), 이메일 회원가입/로그인, `POST /api/reports` DB 저장, Docker 배포 |
| 🔶 데모 | AI·포인트·관리자 데이터 — **FE mock** (`VITE_USE_MOCK`) |
| ⏳ 설계·코드 | FastAPI+YOLO+Gemini 파이프라인, Kafka, GCS, JWT |

**데모 팁**
- 사전에 로그인·제보 1건 **캐시**해 두고, 현장은 "제보 → AI 결과"만 보여도 됨
- mock임을 **슬라이드 각주** 또는 입으로 1회만 언급 (숨기지 말 것)

**멘트 예시**  
> "지금 화면은 End-to-End UX를 mock AI로 시연하고, 제보 저장과 회원 API는 Spring Boot에 연결해 두었습니다."

### ⑤ 기술·구현 현황 (30초) — 슬라이드 07

**목표**: 팀 역량 신뢰 — **아키텍처 전체 X, 레이어만**

| 레이어 | 스택 (한 줄씩) |
|--------|----------------|
| FE | React 19 · Vite · Tailwind v4 · Redux-Saga |
| BE | Spring Boot 4 · MySQL · JPA |
| AI | YOLOv8n + Custom AC 모델 + Gemini 2.5 Flash (Vertex) |
| Infra | Docker Compose · ubuntu03 (FE:8081, BE:8080) |

- **비동기 설계**: Kafka `ECO_POINT_TOPIC` (Producer/Consumer 코드 존재, 운영 연동 P1)
- **이미지**: GCS 비공개 버킷 설계 (현재 placeholder URL)

**시각 자료**: [6_시스템구조.md](../최종%20제안서/6_시스템구조.md) 다이어그램 **1장 축소판**만

### ⑥ 기대효과·마무리 (30초) — 슬라이드 08, 10

**기대효과 (15초, 숫자 1개)**

- 100개 강의실 캠퍼스: 월 **600~1,000 kWh** 절약 잠재 / 또는 연간 **수천만 원** 규모
- 확장: 전국 대학·오피스·아파트 공용부

**마무리 (15초)**

- **핵심 메시지 반복**: "사진 한 장이 캠퍼스 전기료를 줄입니다."
- **링크**: GitHub · 배포 URL(준비 시) · Q&A
- 팀 소개 슬라이드(09)는 **시간 없으면 표지에 이름만** — 5분이면 팀 상세는 생략 가능
