# 7. 구현 상세

> 각 스택에서 사용한 기술적 특징 및 현재 구현 상태

---

## Front-End

### React 19 + Vite + TypeScript

- **파일 기반 자동 라우팅**: `src/pages/url/` 하위 `.tsx`가 자동 등록 (`router.tsx`), `Page` 접미사 제거·소문자 변환
- **모바일 우선 UI**: 최대 너비 390px, 하단 탭 네비게이션(홈·제보·포인트)
- **Redux Toolkit + redux-saga**: `reduxStore.tsx`에 slice·saga 등록, 비동기 API 호출 처리
- **Axios 클라이언트**: `src/globals/api/client.tsx`, `VITE_API_HOST` 환경변수로 API baseURL 설정

### UI/UX

- **TailwindCSS v4**: `@tailwindcss/vite` 플러그인, `src/styles/variables.css` shadcn 토큰(oklch)
- **shadcn/ui + Radix UI**: Button, Card, Input 등 공통 컴포넌트
- **i18next**: 한국어/영어 (`src/assets/locales/`)
- **Pretendard** 폰트 번들 포함

### 인증·제보 플로우

- **카카오 OAuth UI**: `Auth.tsx` — "카카오로 시작하기" 버튼, OAuth2 연동 준비
- **제보 플로우**: 카메라 `<input capture="environment">`, 갤러리 선택, 건물·강의실 선택, AI 결과·포인트 표시
- **홈·포인트·관리자 대시보드**: P0 화면 구현 목표

## Back-End

### Spring Boot 레이어드 아키텍처

```
Controller → Service(interface/impl) → Repository → Entity
```

- **응답 규격**: 성공 `ApiResponse<T> { code, body }` (ResponseCode), 실패 `ApiErrorResponse { code, message }` (ErrorCode)
- **전역 예외 처리**: `ControllerAdvice`에서 `BusinessLogicException` 일괄 처리
- **Swagger**: springdoc-openapi 3.0.2 — `http://localhost:8080/swagger-ui.html`
- **Actuator**: `http://localhost:8080/actuator/health`

### 인증

- **JWT**: Spring Security 기반 (SecurityConfig — 현재 필터 체인 주석 처리, 개발 중)
- **OAuth2 카카오**: `CustomOAuth2UserService` — kakao provider, email·profile 파싱
- **MemberAuthService**: 일부 스텁 (QueryDSL, BCrypt 미연결 시 always true 반환)

### 제보·포인트

- **제보 API**: Report CRUD, GCS 이미지 업로드 연동 (구현 진행)
- **Kafka 포인트 비동기 처리**:
  - `PointProducer`: `KafkaTemplate` → `ECO_POINT_TOPIC` 발행
  - `PointConsumer`: `@KafkaListener(groupId = "eco-point-group")` — 포인트 적립 처리
- **CORS**: `WebConfig` — `allowedOriginPatterns("*")` 전체 허용 (개발)

### DB

- **JPA/Hibernate**: `DDL auto: update`, MySQL localhost:3306
- **엔티티**: Member, Building, Location, ResourceType, LocationResource, Report, Schedule, PointTransaction

## AI

### FastAPI AI Service (Cloud Run)

- **엔드포인트**: `POST /analyze` — 이미지 POST → JSON 분석 결과 반환
- **배포**: Cloud Run (duyuthon 프로젝트, us-central1)

### 3단계 파이프라인

| 단계 | 구현 | 설정 |
|------|------|------|
| 1 | YOLOv8n `yolov8n.pt` | conf=0.3, classes=[0,56,60] person/chair/desk |
| 2 | YOLOv8n Custom `ac_best.pt` | conf=0.4, Roboflow 2,016장, mAP 0.990 |
| 3 | Gemini 2.5 Flash | Vertex AI, 시나리오 A/B 프롬프트, JSON 파싱 |

- **Gemini 프롬프트**: 시나리오 A(원본+크롭 2장 → ac_status, light_status), 시나리오 B(원본 1장 → light_status)
- **응답 처리**: Markdown 코드블록 strip 후 JSON 파싱
- **절약량 계산**: 규칙 기반 엔진 (전기 kWh, 수도 L, 포인트 = 절약금액 × 0.18)

### 어뷰징 필터

- 동일 location 1시간 내 중복, 1일 20건 캡, 야간 보류, 동일 IP 5계정 — 규칙 기반 (BE 연동)

## Infra

### Docker Compose (로컬)

```bash
bash deploy.sh          # FE:8081 + BE:8080 + MySQL:3306
bash deploy.sh down     # 중지
bash deploy.sh cloudrun # GCP Cloud Run 배포
```

- **FE**: Vite build → nginx, `VITE_API_HOST` 빌드 타임 주입
- **BE**: Spring Boot multi-stage Dockerfile
- **MySQL**: 8.4, DB명 `DBname`

### GCP Cloud Run

- **BE**: `ecoreport-be` (asia-northeast3)
- **FE**: `ecoreport-fe`, BE URL 조회 후 `VITE_API_HOST` bake-in
- **AI**: FastAPI 별도 Cloud Run 인스턴스 (YOLOv8 + Gemini)

### 학교 서버

- **MySQL**: SSH 터널링(포트 7540), 이은총 구축
- **Docker**: 김해준 설치, Git clone 후 BE 배포 스크립트
- **포트**: BE 8081 내부 기동, 외부 포트 개방 IT팀 신청 예정

### 보안

- DB 접속 정보 Git 노출 → `.env.example` 전환, 실제 값은 별도 채널 공유
- GitHub Secret Scan 알림 대응
