# 7. 구현 상세

> 각 스택의 **현재 구현 상태**와 **목표 설계**를 구분해 기술한다.

## Front-End

### React 19 + Vite + TypeScript

- **파일 기반 자동 라우팅**: `src/pages/url/` 하위 `.tsx`가 자동 등록 (`router.tsx`)
- **모바일 우선 UI**: 최대 너비 390px, 하단 탭 5개 — 홈·낭비 제보·제보 이력·포인트샵·마이페이지
- **Redux Toolkit + redux-saga**: `reduxStore.tsx`에 slice·saga 등록
- **Axios 클라이언트**: `src/globals/api/client.tsx`, `VITE_API_HOST`로 API baseURL 설정

### 화면 라우트 (구현 완료)

| 경로 | 화면 |
|------|------|
| `/`, `/login`, `/signup` | 홈, 로그인, 회원가입 |
| `/report-form`, `/report-success` | 제보 작성·완료 |
| `/reports`, `/reports/:reportId` | 제보 이력·상세 |
| `/shop`, `/profile` | 포인트샵, 마이페이지 |
| `/admin`, `/admin/reports`, `/admin/buildings`, `/admin/points`, `/admin/stats`, `/admin/users` | 관리자 6화면 |

### UI/UX

- **TailwindCSS v4** + **shadcn/ui** + **Pretendard** 폰트
- **i18next**: 한국어/영어
- **recharts**, **framer-motion**: 관리자 차트·애니메이션
- **마스코트 이미지**: `fe/src/assets/mascort/` (AI 결과 피드백용)

### Mock vs Real API

- **`VITE_USE_MOCK`**: 미설정 또는 `true`이면 mock 사용 (기본값 mock)
- **mock AI**: `simulateAiAnalysis()` — 파일명 휴리스틱 + 3~5초 지연으로 AI UX 시뮬레이션
- **mock 포인트·제보·관리자**: `src/globals/api/mock/data.ts` 기반
- **`VITE_USE_MOCK=false`** 시 buildings·points·reports·제보 저장은 BE 연동 가능; **AI·관리자**는 BE 미구현으로 mock 폴백

### 인증·제보 플로우

- **이메일 로그인/회원가입**: BE `/login`, `/register` 연동 ✅ — JWT `accessToken` + Axios `Bearer`
- **Google OAuth**: BE OAuth2 → FE `/oauth/callback?token=...` ✅
- **카카오 OAuth UI**: 버튼만 존재, BE provider 미등록
- **제보 플로우**: 카메라·갤러리·`GET /api/buildings` → `POST /api/reports` (회원 FK 저장) → FE `simulateAiAnalysis` (BE AI 전까지)

## Back-End

### Spring Boot 레이어드 아키텍처

```
Controller → Service → Repository → Entity
```

- **응답 규격**: `ApiResponse<T>` / `ApiErrorResponse` + `ControllerAdvice`
- **Swagger**: `http://localhost:8080/swagger-ui.html`
- **Actuator**: `http://localhost:8080/actuator/health`

### 현재 API (주요)

| Method | Endpoint | 동작 |
|--------|----------|------|
| GET | `/ping` | 서버 상태 |
| POST | `/login` | BCrypt 검증 + JWT 발급 (`memberSeq` claim) |
| POST | `/register` | 회원 생성 + `MemberPoint` 0P |
| GET | `/register/check-email`, `/register/check-username` | 중복 확인 |
| GET | `/api/buildings` | 건물 목록 (시드 4건 + 정적 locations) — JWT 필요 |
| GET | `/api/points/me` | 잔액 (`currentBalance`; 월/누적은 0) — JWT 필요 |
| POST | `/api/reports` | 제보 저장 (`member`, `PENDING`, placeholder image) — JWT 필요 |
| GET | `/api/reports/me` | 내 제보 목록 (page, size, status) — JWT 필요 |
| GET | `/api/reports/{reportId}` | 제보 상세 (본인만) — JWT 필요 |

### 인증

- **SecurityConfig**: OAuth2 Resource Server JWT + `/login`, `/register` 등 `permitAll`, 그 외 `authenticated`
- **MemberAuthService**: BCrypt + JPA 로그인 검증 ✅
- **JWT**: HS256 발급·검증 ✅ — 제보·포인트·건물 API에서 `@AuthenticationPrincipal Jwt` → `memberSeq`

### 제보

- **ReportService**: JWT 회원·Building 조회 → WasteType → Report INSERT (`member_seq` 저장)
- **조회**: `getMyReports`, `getReportDetail` — 페이지네이션·상태 필터·소유권 검증
- **이미지**: GCS 미연동, placeholder URL
- **AI·포인트 적립·Kafka 발행**: 미연동 (`aiResult` null, `pointAwarded` 0)

### Kafka (코드만)

- `PointProducer` / `PointConsumer` 존재, 토픽 `member-point-topic`
- `application.yaml`: `spring.kafka.listener.auto-startup: false`
- Docker Compose에 Kafka 없음, Producer 호출 코드 없음

### DB 엔티티 (현재)

| 엔티티 | 설명 |
|--------|------|
| Member | userName, password(BCrypt), email |
| Building | 건물 정보 |
| Report | member, building, locationDetail, wasteType, imageUrl, status |
| MemberPoint | 가입 시 생성, `GET /api/points/me` (Kafka 적립 연동 예정) |
| Building | 시드 4건 (`BuildingDataInitializer`); Location 테이블 없음 — locations는 API DTO 상수 |

## AI

### 목표: FastAPI AI Service (Cloud Run)

- **엔드포인트**: `POST /analyze`
- **3단계**: YOLOv8n → YOLOv8n Custom (`ac_best.pt`, mAP 0.990) → Gemini 2.5 Flash
- **별도 저장소**에 구현·배포 (본 monorepo 미포함)

### MVP 데모: FE Mock

```typescript
// fe/src/globals/api/mock/simulator.ts
simulateAiAnalysis() → WASTE_DETECTED | PASS | ERROR + mock 포인트
```

파일명에 `error`/`pass` 포함 시 결과 분기, 기본은 WASTE_DETECTED.

## Infra

### Docker Compose (운영 중)

```bash
bash deploy.sh    # be/deploy.sh → fe/deploy.sh
```

| 서비스 | 포트 | 컨테이너 |
|--------|------|----------|
| FE (nginx) | 8081 | `ecoreport-fe` |
| BE (Spring Boot) | 8080 | `ecoreport-be` |
| MySQL 8.4 | 3306 (내부) | `ecoreport-mysql` |

**학교 서버 `ubuntu03`** (운영 IP는 `.env`의 `DEPLOY_PUBLIC_HOST` 참고): 위 3컨테이너 24시간 가동. Kafka·Cloud Run 미배포.

### 미구현 배포

- `bash deploy.sh down` / `cloudrun` — 루트 스크립트에 없음
- GCP Cloud Run, GCS 버킷 — 목표 인프라

- 카카오 OAuth provider·FE 리다이렉트
- Kafka Compose 추가 및 PointProducer 연동
- 관리자 대시보드 API + FE mock 제거
- GitHub Actions CI/CD, Cloud Run 배포
