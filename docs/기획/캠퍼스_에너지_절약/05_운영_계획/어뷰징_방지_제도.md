# 어뷰징 방지 제도 (Anti-Abuse Policy)

> **대표 시나리오**: 불이 꺼져 있는 강의실에서 조명·에어컨을 **직접 켠 뒤** 사진을 찍어 포인트를 받아가는 행위  
> **관련 리스크**: [리스크_관리.md](./리스크_관리.md) R1 · **기술 규칙**: [AI_모델_설계.md](../04_기술_기획/AI_모델_설계.md) §4

## 1. 핵심 한계

현재 AI는 **「지금 조명/에어컨이 켜져 있고, 사람이 없으며, 운영 시간 외인가?」**만 판단한다.  
**「누가 켰는가」**는 단일 사진만으로는 알 수 없다.

| AI가 할 수 있는 것 | AI가 할 수 없는 것 |
|-------------------|-------------------|
| 조명·에어컨 ON/OFF 감지 | 제보자가 스위치를 켰는지 여부 |
| 사람·의자·책상 유무 확인 | 촬영 직전 전원 상태 |
| 운영 스케줄 대비 제보 시각 검증 | 악의적 의도 판별 |

**설계 원칙**: 완전 차단이 아니라 **「악용 이득 < 전기료 + 제재 + 시간 비용」**이 되도록 다층 방어를 겹친다.  
**잔여 리스크**: 최초 1회성 「켜고 찍기」는 기술만으로 차단 불가 — **수용**하고 사후·경제적 장치로 완화한다.

## 2. 4단계 방어 레이어

```
제보 접수
    │
    ├─ [L1 사전 차단] ─────────────────────────────────────────────
    │     ├─ 운영 시간 중? ──────────────► 즉시 반려 ✅
    │     ├─ 본인이 이미 제보한 강의실? ──► 즉시 반려 ✅ (영구 1회)
    │     ├─ 1시간 내 동일 강의실? ──────► 즉시 반려 ⏳
    │     ├─ 오늘 20건 초과? ────────────► 반려 + 경고 ⏳
    │     └─ 야간(00~06시)? ─────────────► 보류 ⏳
    │
    ├─ [L2 AI·촬영 조건] ──────────────────────────────────────────
    │     ├─ 사람 감지 → PASS (반려)
    │     ├─ 의자·책상 미탐지 → ERROR (반려)
    │     └─ WASTE_DETECTED → L3으로
    │
    ├─ [L3 지급 구조] ─────────────────────────────────────────────
    │     ├─ MVP: AI 통과 즉시 적립 ✅
    │     └─ P1: 24~48h 지연 확정 / 소등 확인 후 본 포인트 ⏳
    │
    └─ [L4 사후·운영] ─────────────────────────────────────────────
          ├─ 관리자 이의 신청 → 포인트 회수 ⏳
          ├─ 이상 패턴 알림 → 검토 큐 ⏳
          └─ 반복 적발 → 계정 경고·정지 ⏳
```

### L1 — 사전 차단 (규칙)

| 규칙 | 효과 | 구현 |
|------|------|------|
| **운영 시간 외만 제보** | 수업 중 「켜고 찍기」 차단 | ✅ `isReportableAt()` |
| **강의실당 1인 1회** | 같은 방 반복 수익화 불가 | ✅ `ALREADY_EXISTS` (2004) |
| **1시간 내 동일 강의실 중복** | 협력·다계정 반복 차단 | ⏳ |
| **1일 20건 캡** | 대량 어뷰징 차단 | ⏳ |
| **야간(00~06시) 보류** | CCTV·관리 부재 시간대 수동 검토 | ⏳ |
| **동일 IP 5계정 이상** | 다계정 봇 차단 | ⏳ |

### L2 — AI·촬영 조건 (기술)

| 조건 | 처리 | 비고 |
|------|------|------|
| 운영 시간 외 + 빈 강의실 | 제보 가능 | Gemini + `operatingSchedules` |
| 사람 0명 | 통과 조건 | 켜고 나가기 전 촬영 시 통과 가능 (한계) |
| 의자·책상 필수 | 강의실 아닌 공간 남용 차단 | YOLO chair/desk |
| EXIF 촬영 시각 검증 | 갤러리 옛 사진 업로드 차단 | ⏳ Phase 2 |
| GPS·와이파이 SSID | 캠퍼스·건물 내 제보만 허용 | ⏳ Phase 2 |

### L3 — 지급 구조 (경제·제도) ★ 핵심

즉시 지급은 UX에 유리하지만 「켜고 찍기」 1회도 바로 수익이 된다.  
**악용 ROI를 낮추는** 지급 설계:

| 방식 | 설명 | 우선순위 |
|------|------|----------|
| **지연 지급 (24~48h)** | 관리자·시설팀 소등 확인 후 포인트 확정 | P1 |
| **확인형 포인트** | 제보 소액 + 소등 확인 후 본 포인트 (예: 50% + 50%) | P1 |
| **월 정산·교환 한도** | 당일 현금화 어렵게 → 사후 회수 여지 | P2 |
| **낮은 단가** | 건물주 절감액의 18%만 포인트 (×0.18) | ✅ |
| **교환 최소 임계** | 500P부터 기프티콘 → 소액 반복 동기 감소 | ⏳ |

**인센티브 정렬**: 포인트는 「낭비 발견」이 아니라 **「실제 절약 기여」**로 정의한다.

```
제보 접수 → (보류) → 시설팀 현장 확인·소등 → 포인트 확정
```

### L4 — 사후·운영 (제재·거버넌스)

| 수단 | 내용 | 구현 |
|------|------|------|
| **관리자 이의 신청** | 「원래 꺼져 있었음」 확인 시 포인트 회수 | A-05 ⏳ |
| **이상 패턴 알림** | 짧은 시간·다강의실 연속 제보 → 검토 큐 | ⏳ |
| **계정 경고 → 정지** | 반복 시 ROLE 제한, 교환 동결 | ⏳ |
| **이용약관·벌칙** | 「고의적 낭비 유발 제보」 명시 → 몰수·정지 | ⏳ |
| **실명·학번 가입** | 익명 대량 가입 어뷰징 방지 | ✅ (회원가입) |

## 3. 시설팀 검증 루프

크라우드소싱의 **검증 주체**를 AI만이 아니라 **관리자·시설팀**으로 둔다.

| 단계 | 주체 | 행동 |
|------|------|------|
| 1 | 학생 | 낭비 사진 제보 |
| 2 | BE + AI | 1·2차 자동 판별 |
| 3 | 시설팀 | 대시보드 알림 → 현장 확인·소등 |
| 4 | 시설팀 | 정상 제보 → 포인트 확정 / 어뷰징 의심 → 이의 신청 |
| 5 | 플랫폼 | 이의 인정 시 포인트 회수 + 계정 경고 |

## 7. Q&A (발표용)

**Q. 조명을 일부러 켜고 찍으면 어떻게 막나요?**

> 사진 AI만으로는 「누가 켰는지」는 판별할 수 없습니다.  
> **운영시간·1인1회·일일 한도**로 반복을 막고, **포인트는 관리자 확인 후 지급**하며, **적발 시 회수·계정 제한**하는 다층 방어로, 악용 이득이 전기료·제재보다 작게 만듭니다.

**Q. 첫 번째 「켜고 찍기」는 막을 수 없나요?**

> 1회성은 잔여 리스크로 수용합니다. 다만 포인트 단가(절감액 18%)·교환 최소 임계·지연 지급으로 **한 번의 이득을 최소화**하고, 시설팀 이의 신청으로 **사후 회수**합니다.
