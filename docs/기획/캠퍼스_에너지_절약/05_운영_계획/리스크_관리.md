## 2. 리스크 목록 및 대응 계획

### R1 — 어뷰징 (높음/높음) ★최우선

| 항목 | 내용 |
|------|------|
| **설명** | 사용자가 조명을 일부러 켜고 제보, 또는 봇으로 대량 허위 제보 |
| **영향** | 포인트 풀 고갈, 건물주 불신, 서비스 신뢰도 붕괴 |
| **예방** | 동일 위치 1시간 제한, 일일 제보 캡(20건), 야간 보류 |
| **탐지** | 이상 패턴 관리자 알림, 신속한 이의 신청 처리 |
| **완화** | 포인트 확정을 관리자 승인 후로 지연 (P1) |
| **잔여 리스크** | 최초 어뷰징 1회는 차단 불가 — 수용 |

---

### R2 — AI 판별 오류 (중간/중간)

| 항목 | 내용 |
|------|------|
| **설명** | Gemini Vision이 어두운 사진, 역광, 창문 반사 등에서 오판 |
| **영향** | 낭비 미감지(False Negative) → 포인트 미지급 → 사용자 불만 |
| **예방** | 사진 촬영 가이드 UI, confidence 임계값 0.7 |
| **완화** | 판별 불가 시 재촬영 요청, 이의 신청 → 관리자 수동 검토 |

---

### R3 — Gemini API 비용 폭증 (중간/높음)

| 항목 | 내용 |
|------|------|
| **설명** | 제보 폭증 시 API 호출 비용이 포인트 풀 수익을 초과 |
| **예방** | 일일 제보 캡, API 호출 전 어뷰징 사전 필터 |
| **완화** | API 비용 모니터링 알림 설정, 일 예산 상한선(Cap) |
| **해커톤** | GCP 크레딧 $300 무료 범위 내 운용 |

---

### R4 — 건물주 낮은 참여율 (높음/중간)

| 항목 | 내용 |
|------|------|
| **설명** | 건물주가 등록/납부를 꺼리거나 무관심 |
| **영향** | 수익 구조 성립 안 됨 |
| **해커톤 대응** | 대학 시설팀 파트너십 미리 논의 or 데모용 시드 데이터로 대체 |
| **장기 대응** | 무료 체험 기간 제공, 절감 효과 리포트 선제 제공 |

---

### R5 — 개인정보 침해 이슈 (낮음/높음)

| 항목 | 내용 |
|------|------|
| **설명** | 제보 사진에 학생 얼굴 등 개인정보 포함 가능성 |
| **예방** | AI 판별 시 인물 감지 → 사진 업로드 시 얼굴 자동 블러 처리 |
| **법적** | 개인정보보호법 준수, 이미지 보관 기간 제한 (30일) |

---

### R6 — 기술 구현 실패 (낮음/높음)

| 항목 | 내용 |
|------|------|
| **설명** | 해커톤 시간 내 P0 기능 미완성 |
| **예방** | 기능별 시간 버퍼 배정, 가장 중요한 제보 플로우 최우선 구현 |
| **완화** | 미완성 기능은 Mock 데이터로 데모, 발표에서 "향후 구현 예정"으로 처리 |

## 3. 어뷰징 대응 상세 플로우

```
제보 접수
    │
    ├─ 동일 room_id × 1시간 내? ──► 즉시 반려
    │
    ├─ 오늘 제보 20건 초과? ──────► 즉시 반려 + 경고
    │
    ├─ AI 판별 시행
    │       │
    │       ├─ 사람 감지? ──────► 반려 (PEOPLE_PRESENT)
    │       ├─ confidence < 0.7? → 보류 (UNDETECTABLE)
    │       └─ 통과 → 포인트 적립
    │
    └─ 관리자 이의 신청 가능 (48시간 내)
            │
            └─ 이의 인정 → 포인트 회수 + 계정 경고
```

## 4. 개인정보 처리 방침 요약

| 항목 | 정책 |
|------|------|
| 제보 사진 보관 기간 | 판별 완료 후 30일 → 자동 삭제 |
| 얼굴 포함 사진 | AI 블러 처리 후 저장 |
| 위치 데이터 | LocationNode LEAF ID만 저장 (GPS 좌표 미수집) |
| 포인트 정산 정보 | 최소 필요 정보만 수집 (연락처: 교환 신청 시에만) |
