# 수익 구조 상세 (Revenue Model)

---

## 1. 수익 흐름 다이어그램

```
[건물주 / 대학]
       │
       │ 절약된 전기료의 20% 납부
       │ (ex. 이번 달 절약 10만 원 → 납부 2만 원)
       ▼
[에코리포트 플랫폼]
       │
       ├── 10% (플랫폼 수수료) ────────────────► 플랫폼 수익
       │
       └── 90% (포인트 풀) ──────────────────► 학생 포인트 지급
                                               (기프티콘 등 교환)
```

---

## 2. 단위 경제성 (Unit Economics) 시뮬레이션

### 가정
- 1개 건물, 강의실 50개
- 일 평균 낭비 발생 강의실: 10개 (20%)
- 강의실 평균 방치 시간: 2시간
- 조명(40W×10개) + 에어컨(1.5kW): 평균 소비전력 1.9 kW/강의실·시간
- 전기료 단가: 130원/kWh
- 한 달(22영업일) 기준

| 항목 | 계산 | 금액 |
|------|------|------|
| 월 낭비 전기 | 10개 × 2h × 1.9kW × 22일 | 836 kWh |
| 월 낭비 전기료 | 836 × 130원 | 약 108,680원 |
| 건물주 절약분 지급 (20%) | 108,680 × 0.2 | 약 21,736원 |
| 플랫폼 수수료 (10%) | 21,736 × 0.1 | 약 2,174원 |
| 학생 포인트 풀 (90%) | 21,736 × 0.9 | 약 19,562원 |

> 건물 1개 기준 월 수수료 수익 약 2,200원 → **100개 건물 시 월 22만 원, 연 264만 원**

## 3. 손익분기점 분석

> **에너지(전력) 손익분기점** — 플랫폼 소비 전력 vs 캠퍼스 절약 전력 — 은 [서버_전력_및_에너지_손익분기점.md](../04_기술_기획/서버_전력_및_에너지_손익분기점.md) 참고.  
> MVP 기준 **월 ~22건** 실효 제보로 Energy BEP 달성 (재무 BEP **~32개 건물**보다 훨씬 이른 시점).

### 비용 구조 (월간 MVP 운영 기준)

| 항목 | 월 비용 (추정) |
|------|-------------|
| Gemini API (제보 1,000건 기준) | 약 20,000원 |
| GCP 서버 (Cloud Run + DB) | 약 50,000원 |
| 포인트 구매 (학생 교환분) | 수익에서 지출 (포인트 풀에서 충당) |
| **월 고정 지출 합계** | 약 70,000원 |

### 손익분기
- 월 수수료 수입 ≥ 70,000원 → BEP 달성
- 필요 건물 수: 약 32개 건물 (건물당 월 2,200원 수익 기준)

## 4. 중장기 수익 다각화

| 수익원 | 시점 | 예상 규모 |
|--------|------|----------|
| 플랫폼 수수료 (핵심) | 즉시 | 건물 수 비례 |
| 친환경 브랜드 스폰서십 | 6개월 이후 | 월 100만 원 수준 |
| 익명 에너지 낭비 데이터 판매 | 1년 이후 | 에너지 컨설팅사 B2B |
| 공공기관 B2G 솔루션 납품 | 1년 이후 | 지자체·정부기관 |

---

## 5. 어뷰징 발생 시 재무 리스크

| 상황 | 재무 영향 | 대응 |
|------|----------|------|
| 학생이 조명 켜고 허위 제보 | 포인트 과지급, 건물주 불만 | 관리자 이의 신청 → 포인트 회수 |
| 대규모 어뷰징 봇 | 포인트 풀 고갈 | 계정당 일일 제보 건수 캡, AI 탐지 |
| 건물주 납부 거부 | 수익 손실 | 선불 예치금 제도 도입 |
