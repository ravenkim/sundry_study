## 2. 기술 스택

| 레이어 | 기술 | 선택 이유 |
|--------|------|----------|
| Frontend | React 19 + TailwindCSS v4 (모바일 웹) | 모바일 우선 설계, 최대 너비 390px, 하단 탭 네비게이션 |
| Backend | Spring Boot 4.x | 팀 CLAUDE.md 계획 스택, 현재 코드베이스 |
| AI Service | FastAPI (Python) — Cloud Run 별도 인스턴스 | YOLOv8 / Vertex AI Python SDK와 연동 용이 |
| 객체 탐지 | Ultralytics YOLOv8n + YOLOv8n Custom (`ac_best.pt`) | 경량 실시간 탐지, COCO 사전학습 + Roboflow 파인튜닝 |
| 데이터셋 관리 | Roboflow (`office-air-condition` v1) | 에어컨 탐지 학습 데이터 2,016장 |
| 멀티모달 AI | Google Vertex AI — Gemini 2.5 Flash | 해커톤 주제 연계 (Google Cloud), 멀티모달 지원 |
| Database | MySQL | 팀 계획 스택, JPA 연동 용이 |
| 이미지 저장 | Google Cloud Storage | Gemini와 동일 클라우드, 비용 효율 |
| 인프라 | Google Cloud Run | Docker 기반 서버리스 배포 (BE + AI Service 각각) |
| 인증 | JWT (Spring Security) | 현재 코드베이스에 구현됨 |

## 4. AI 판별 처리 흐름

```
[클라이언트]
    │ 사진 파일 업로드
    ▼
[Spring Boot API]
    │ 1. 이미지 → GCS 저장 (비공개 버킷)
    │ 2. AI Service (FastAPI) POST /analyze 호출
    ▼
[AI Service — Cloud Run (FastAPI)]
    │
    ├─ [1단계] YOLOv8n (conf=0.3, classes=[person/chair/desk])
    │       ├─ chair=0 AND desk=0 → ERROR: 강의실 아님
    │       └─ person ≥ 1        → PASS: 사용 중
    │           ↓ (person = 0)
    ├─ [2단계] YOLOv8n Custom ac_best.pt (conf=0.4)
    │       ├─ 에어컨 미탐지 → [3단계 시나리오 B]
    │       └─ 에어컨 탐지   → 크롭 → [3단계 시나리오 A]
    │
    └─ [3단계] Gemini 2.5 Flash (Vertex AI)
            시나리오 A: 원본 + 크롭 2장 → ac_status + light_status
            시나리오 B: 원본 1장        → light_status만
            ├─ 낭비 감지 → WASTE_DETECTED { ac_status, light_status, reason }
            └─ 모두 꺼짐 → PASS
    ▼
[Spring Boot API]
    │ 3. AI 결과 파싱 → Report 저장
    │ 4. 어뷰징 필터 (동일 위치 1시간 내 중복 체크)
    │ 5. 절약량 계산 → 포인트 적립 트랜잭션
    ▼
[클라이언트] ← 결과 반환
```

## 5. 데이터베이스 ERD

> **현재 구현**: `Affiliation` → `LocationNode`(self-ref GROUP/LEAF 트리), `Report` → LEAF, `Member` → Affiliation.  
> **목표 확장**: ResourceType, LocationResource — [자원_관리_설계.md](./자원_관리_설계.md) · [장소_관리_모델.md](./장소_관리_모델.md)

```
Affiliation
  └──< LocationNode (parent self-ref, nodeKind GROUP/LEAF, max depth 3)
              │
              └──< Report >── Member
                        │
                        └──< MemberPoint

[목표] ResourceType ──< LocationResource >── LocationNode (LEAF)
```

**현재 Report**: member_id, location_node_id(LEAF), image_url, status, wasteType

**목표 확장 테이블**:

**ResourceType** *(플랫폼 마스터 — 슈퍼어드민 관리)*:  
id, category(ELECTRICITY/WATER), name, unit, default_value, detection_hint, icon_code, is_active

**LocationResource**: id, location_node_id, resource_type_id, quantity, custom_value, is_reportable

**Report** *(목표)*: location_resource_id, ai_result(JSON), point_awarded

**Schedule**: id, location_id, day_of_week, start_time, end_time (수업/예약 시간)

**PointTransaction**: id, member_id, amount, type(EARN/REDEEM), reference_id, created_at

## 6. 배포 구성

### 6.1 현재 구현 (저장소 스크립트)

| 환경 | 명령 | 구성 |
|------|------|------|
| 로컬 통합 | 루트 `bash deploy.sh` | `be/deploy.sh` → `fe/deploy.sh` → `docker-compose.yml`로 MySQL 8.4 + BE(8080) + FE(8081, nginx) |
| BE 단독 | `be/deploy.sh` | MySQL(미기동 시) + BE Compose 빌드·기동 |
| FE 단독 | `fe/deploy.sh` | FE Compose 빌드·기동 (Vite build → nginx, 루트 `.env`의 `VITE_API_HOST` build ARG) |

상세 절차·환경 변수·트러블슈팅: [배포_가이드.md](./배포_가이드.md)

### 6.2 Cloud·AI 인프라

| 구성 | 상태 | 비고 |
|------|------|------|
| **AI FastAPI (Cloud Run)** | ✅ 배포·BE 연동 | `us-central1`, `POST /analyze` |
| **BE Cloud Run** | ⏳ 예정 | asia-northeast3 목표 |
| **FE Cloud Run** | ⏳ 예정 | asia-northeast3 목표 |
| **Cloud SQL** | ⏳ 예정 | 운영 DB 연동 |
| **GitHub Actions CI/CD** | ⏳ 예정 | |

```
Docker Compose (ubuntu03: FE·BE·MySQL)     GCP Cloud Run (us-central1: AI FastAPI)
       │                                              ▲
       └─ BE POST /api/reports ── HTTP ──────────────┘
```

> AI Service는 Spring Boot BE와 **별도 Cloud Run 인스턴스**로 배포되어 있다.  
> 모델 파일(`yolov8n.pt`, `models/ac_best.pt`)은 Docker 이미지 빌드 시 포함되며, 인스턴스 기동 시 전역으로 한 번만 메모리에 로드된다.

## 7. 해커톤 MVP 범위 (달성 현황)

해커톤 P0 목표 대비 현재 상태:

- Spring Boot 백엔드 기본 API (회원, 제보, 포인트) — ✅
- **FastAPI 3단계 AI 파이프라인 + BE `/analyze` 호출** — ✅ (Cloud Run 배포)
- React 모바일 웹앱 (홈, 제보 플로우, 포인트 확인) — ✅
- **관리자 장소 관리 UI + location-nodes API** — ✅
- 관리자 제보·대시보드 UI — ✅ (데이터 mock, BE ⏳)
- MySQL 연동 — ✅
- MySQL + **GCS** 연동 — ⏳ (placeholder URL)
- 포인트 적립·Kafka — ⏳

## 8. monorepo `ai/` 요약

학습·추론·배포 코드는 저장소 루트 `ai/`에 위치한다. BE는 제보 생성 시 Cloud Run FastAPI를 호출하며, FE `simulateAiAnalysis()`는 3단계 진행 UI 시연용으로만 사용한다. 배포·로컬 실행 방법은 [배포_가이드.md §11](./배포_가이드.md)을 참고한다.
