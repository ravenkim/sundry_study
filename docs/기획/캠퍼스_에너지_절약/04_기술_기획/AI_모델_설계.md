## 2. Gemini Vision API 활용

### 모델
- `gemini-1.5-flash` (속도·비용 균형)
- 이미지 1장당 API 호출 1회

### 프롬프트 설계

```
System:
당신은 건물 에너지 낭비를 탐지하는 AI입니다.
사진을 분석하여 다음을 판별하세요:
1. 조명(형광등, LED 등)이 켜져 있는가?
2. 에어컨, 히터, 선풍기 등 전열기구가 작동 중인가?
3. 강의실/공간에 사람이 있는가?

반드시 다음 JSON 형식으로만 응답하세요:
{
  "lighting_on": boolean,
  "hvac_on": boolean,
  "people_present": boolean,
  "confidence": float (0.0~1.0),
  "detected_devices": [string]
}

User:
[이미지 첨부]
이 강의실 사진을 분석해주세요.
```

### 판별 로직

```
if (people_present == true):
    → 제보 반려 ("수업/재실 중인 강의실입니다")

elif (lighting_on == false AND hvac_on == false):
    → 제보 반려 ("낭비 감지되지 않음")

elif (confidence < 0.70):
    → 제보 보류 ("판별 불가 — 더 밝은 사진으로 재촬영 요청")

else:
    → 제보 승인 + 포인트 산정
```

## 3. 절약량 계산 엔진

### 입력 데이터
- `devices`: 건물주가 등록한 강의실 전열기구 목록 및 소비전력(W)
- `off_time`: 제보 시각 ~ 다음 수업 시작 시각 (시간표 연동 시) 또는 고정 기본값 2시간
- `electricity_rate`: 건물 단가 (기본값: 130원/kWh)

### 계산 공식

```
kWh = Σ(device_power_W) / 1000 × off_time_hours
예상_절약_전기료 = kWh × electricity_rate
포인트 = 예상_절약_전기료 × 0.18  (건물주 납부 20% × 학생 몫 90%)
```

### 예시
- 강의실: 조명(40W×10개=400W) + 에어컨(1,500W) = 1,900W
- 방치 시간: 2시간
- kWh: 1.9 × 2 = 3.8 kWh
- 전기료: 3.8 × 130 = 494원
- 포인트: 494 × 0.18 ≈ **89포인트**

## 4. 어뷰징 탐지 규칙

| 규칙 | 임계값 | 처리 |
|------|-------|------|
| 동일 강의실 중복 제보 | 1시간 내 같은 room_id | 두 번째부터 자동 반려 |
| 단기간 과다 제보 | 1일 20건 초과 | 계정 경고 + 제보 잠금 |
| 야간 시간대 제보 | 자정~06시 | 자동 보류 → 관리자 수동 검토 |
| 동일 IP 다중 계정 | 같은 IP 5계정 이상 | 신규 제보 차단 |
