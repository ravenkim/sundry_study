# 자원 관리 설계 — 확장 가능한 자원 유형 체계

> 강의실 조명에 국한되지 않고 전기·수도 등 모든 낭비 자원을 관리자가 자유롭게 등록할 수 있는 구조

> **현재 구현 (2026-05-24)**: `LocationNode` 트리(GROUP/LEAF) + 관리자 `/api/admin/location-nodes` CRUD + FE 장소 관리 UI.  
> **Phase 1 (공모전 MVP) ✅**: LEAF 자원 수량 + **요일별 운영시간** + **AI(Gemini) `expected`(원) 기반 절약량·포인트 산출**.  
> **Phase 2 (P1 목표)**: `ResourceType`, `LocationResource` — 아래 전체 설계는 목표 스키마.  
> 장소 트리 상세: [장소_관리_모델.md](./장소_관리_모델.md)

## Phase 1 (공모전 MVP) — LEAF 컬럼

해커톤·공모전 범위에서는 별도 `ResourceType`/`LocationResource` 테이블 없이, **LEAF(항목) 노드에 전기 자원 수량 3종**을 직접 저장합니다.

### AI vs 절약량 계산 — 역할 분리

| 구분 | 담당 | 입력 |
|------|------|------|
| **낭비 판별 + 절약량** | YOLO + Gemini (`/analyze`) | 사진 + metadata → `ac_status`, `light_status`, `expected`(원), `expectedKwh` |
| **BE 저장** | `ReportService` | `expected` → `estimatedSavingsKrw`, `expectedKwh` → `estimated_kwh`, `estimatedPoint` |
| **건물 집계** | `GET /api/savings/buildings/me` | 본인 제보 `estimated_kwh` 건물별 SUM |
| **참고용 규칙 엔진** | BE `SavingsCalculationService` | 제보 플로우 미사용 — Phase 2·검증용 |

### DB 컬럼 (`location_node_db`, LEAF만 사용)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `ac_count` | INT NOT NULL DEFAULT 0 | 에어컨 대수 |
| `fluorescent_count` | INT NOT NULL DEFAULT 0 | 형광등 개수 |
| `led_count` | INT NOT NULL DEFAULT 0 | LED 조명 개수 |

GROUP 노드는 항상 0. API Create/Update 시 LEAF일 때만 값 반영.

### DB 테이블 (`location_operating_schedule_db`, LEAF당 7행)

조명·에어컨 **공통** 운영시간. LEAF당 월~일 7행.

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `location_node_seq` | FK | LEAF 노드 |
| `day_of_week` | TINYINT | 1=월 … 7=일 |
| `is_closed` | BOOLEAN | 휴무일 (일요일 등) |
| `power_on_time` | TIME | 켜는 시간 |
| `power_off_time` | TIME | 끄는 시간 |

**기본값**: 월~금 07:00~22:00, 토 08:00~18:00, 일 휴무.

### 제보 스냅샷 (`report_db`)

| 컬럼 | 설명 |
|------|------|
| `created_at` | 제보 시각 (서버 자동 저장, NOT NULL) |
| `off_time_minutes` | 산출 방치 시간(분) |
| `estimated_kwh` | 예상 절약 kWh |
| `estimated_savings_krw` | 예상 절약 금액(원) |
| `estimated_point` | 예상 포인트 (AI 산출, UI 표시용) |
| `point_awarded` | 확정 포인트 (AI 판별 직후 적립) |

### Phase 1 입력 (관리자)

| 항목 | MVP | 비고 |
|------|-----|------|
| 에어컨/형광등/LED 수량 | ✅ | |
| 요일별 켜는/끄는 시간 | ✅ | 7일, `is_closed` 지원 |
| W / 에너지등급 | ❌ | 기본 W 상수 |
| 수업 시간표 | ❌ | Phase 2 |

### 기본 소비전력 상수 (Phase 1)

| 자원 | default W | 근거 |
|------|-----------|------|
| 형광등 | 40 | ResourceType 목표값 |
| LED 조명 | 20 | ResourceType 목표값 |
| 에어컨 | 1500 | ResourceType 목표값 (중형 벽걸이 기준) |

### Phase 1 절약량 공식

```
kWh_형광등 = 40 × fluorescent_count / 1000 × off_time_hours
kWh_LED    = 20 × led_count / 1000 × off_time_hours
kWh_에어컨 = 1500 × ac_count / 1000 × off_time_hours   (AI가 ac ON일 때만)
총 kWh = Σ (AI가 ON으로 판별한 자원만 합산)
절약 금액 = 총 kWh × 130 (원/kWh, 기본 단가)
포인트 = 절약 금액 × 0.18
```

### 방치 시간(`off_time`) — `SavingsCalculationService`

입력: `report.createdAt`, 해당 요일 `location_operating_schedule_db` 1행

| 조건 | off_time (분) |
|------|---------------|
| `is_closed=true` (휴무일) | min(120, 제보~자정) |
| 제보 < power_on | min(120, power_off − 제보) |
| power_on ≤ 제보 < power_off | power_off − 제보 |
| 제보 ≥ power_off | min(120, 자정까지) |
| 스케줄 없음 (레거시) | 120 (2시간 fallback) |

### Phase 2 이후 (본 문서 §2~)

- `ResourceType` 마스터 + `LocationResource`로 임의 자원(수도꼭지 등) 확장
- `custom_value`로 방별 실제 W override
- **수업 시간표(`Schedule`)** 연동으로 방치 시간 정밀화

## 1. 핵심 설계 원칙

기존 설계의 문제:
- `Room.devices` 필드가 JSON으로 기기 목록 저장 → 타입 추가 시 코드 변경 필요
- "강의실"만 지원 → 화장실·복도·사무실·주방 등 확장 불가
- AI 프롬프트가 조명·에어컨으로 하드코딩

**변경 방향**: 관리자가 DB를 통해 자원 유형을 직접 등록·관리.  
코드 배포 없이 새 자원(커피포트, 수도꼭지, 정수기 등) 추가 가능.

## 2. 자원 분류 체계

### 최상위 분류: ResourceCategory (자원 분류)

| 분류 코드 | 이름 | 단위 기준 | 절약량 계산 방식 |
|-----------|------|----------|----------------|
| `ELECTRICITY` | 전기 | W (와트), kWh | 소비전력 × 낭비 시간 × 전기 단가 |
| `WATER` | 수도 | L/min (분당 리터) | 유량 × 낭비 시간 × 수도 단가 |

> 향후 `GAS`(도시가스), `HEAT`(냉난방열) 분류 추가 가능

---

### 세부 유형: ResourceType (자원 유형)

관리자가 플랫폼 설정에서 등록하는 마스터 데이터.

| 필드 | 타입 | 설명 |
|------|------|------|
| `id` | Long | PK |
| `category` | ENUM | ELECTRICITY / WATER |
| `name` | String | 유형 이름 (예: "형광등", "에어컨", "커피포트") |
| `unit` | String | 단위 레이블 (예: "W", "L/min") |
| `default_value` | Double | 카테고리별 기본 소비량 (전기: W, 수도: L/min) |
| `detection_hint` | String | AI 프롬프트에 주입할 탐지 힌트 (예: "천장에 붙은 형광등") |
| `icon_code` | String | 프론트엔드 아이콘 코드 |
| `is_active` | Boolean | 비활성화 시 신규 등록 불가 |

**기본 제공 ResourceType 예시**

| category | name | default_value | unit | detection_hint |
|----------|------|-------------|------|----------------|
| ELECTRICITY | 형광등 | 40 | W | 천장에 설치된 형광등 또는 LED 조명 |
| ELECTRICITY | LED 조명 | 20 | W | 천장에 설치된 LED 조명 |
| ELECTRICITY | 에어컨 | 1500 | W | 벽걸이형 또는 스탠드형 에어컨 |
| ELECTRICITY | 히터/전열기 | 1000 | W | 전기 히터, 라디에이터 |
| ELECTRICITY | 커피포트 | 1200 | W | 전기 주전자, 커피메이커 |
| ELECTRICITY | 냉장고 | 150 | W | 소형 냉장고 (문 열림 감지 불포함) |
| ELECTRICITY | 컴퓨터/모니터 | 200 | W | PC 본체 및 모니터 |
| ELECTRICITY | 선풍기 | 50 | W | 선풍기, 서큘레이터 |
| WATER | 수도꼭지 | 8 | L/min | 세면대 또는 싱크대 수도꼭지 |
| WATER | 샤워기 | 10 | L/min | 샤워기 헤드에서 흐르는 물 |
| WATER | 정수기 | 3 | L/min | 냉온수 정수기 출수구 |

## 4. 장소-자원 연결: LocationResource

특정 장소에 어떤 자원이 몇 개 설치되어 있는지 관리자가 등록.

| 필드 | 타입 | 설명 |
|------|------|------|
| `id` | Long | PK |
| `location_id` | Long | FK → Location |
| `resource_type_id` | Long | FK → ResourceType |
| `quantity` | Integer | 설치 수량 (예: 조명 10개) |
| `custom_value` | Double | null이면 ResourceType.default_value 사용 |
| `is_reportable` | Boolean | 이 자원에 대한 제보 허용 여부 |
| `notes` | String | 관리자 메모 |

**예시: 공학관 A동 303호**

| 자원 유형 | 수량 | custom_value |
|----------|------|-------------|
| 형광등 | 10 | null (40W 기본값) |
| 에어컨 | 1 | 2000 (해당 기기 실제 소비전력) |
| 커피포트 | 1 | null |

**예시: 1층 공용 화장실**

| 자원 유형 | 수량 | is_reportable |
|----------|------|--------------|
| 수도꼭지 | 4 | true |
| 형광등 | 6 | true |

## 6. 절약량 계산 — 자원 분류별 공식

```
[ELECTRICITY]
절약 kWh = (custom_value OR default_value W) × quantity × off_time_hours / 1000
절약 금액 = kWh × electricity_rate (원/kWh, 건물별 단가)

[WATER]
절약 L = (custom_value OR default_value L/min) × quantity × off_time_minutes
절약 금액 = L × water_rate (원/L, 건물별 단가)

포인트 = 절약 금액 × 0.18  (건물주 납부 20% × 사용자 몫 90%)
```

## 7. 관리자 등록 UX 플로우

**현재 구현** — [장소_관리_모델.md](./장소_관리_모델.md) · FE `/admin/buildings` (장소 관리):

```
[관리자]
    │
    ├─ 1. 소속 고정 (JWT scope, select 없음)
    ├─ 2. 1·2·3단계 컬럼에서 GROUP/LEAF 탐색
    ├─ 3. Sheet로 노드 추가·수정·삭제 (location-nodes API)

```

**목표 (P1)** — ResourceType·LocationResource 연동 후:

```
[관리자]
    │
    ├─ 1. 장소 트리 관리 (LocationNode) ✅
    ├─ 2. LEAF 노드에 자원 등록 (LocationResource)
    │       자원 유형 선택 (ResourceType 마스터) → 수량 + 소비량
    └─ 3. (선택) 시간표 등록 (Schedule)
```


## 9. 플랫폼 마스터 관리 (슈퍼어드민)

ResourceType은 플랫폼 운영자(슈퍼어드민)만 추가/수정 가능.  
일반 건물 관리자는 기존 ResourceType 목록에서 선택만 가능.

| 권한 | 가능한 작업 |
|------|-----------|
| 슈퍼어드민 | ResourceType CRUD, 건물 승인, 전체 통계 |
| 건물 관리자 | Location CRUD, LocationResource CRUD, 제보 확인, 정산 |
| 사용자 | 제보 생성, 포인트 조회/교환 |
