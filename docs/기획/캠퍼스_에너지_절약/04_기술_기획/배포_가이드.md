# 배포 가이드

EcoReport(FE + BE + MySQL) 로컬 Docker 배포 및 GCP Cloud Run 배포 절차.

---

## 1. 개요

| 구분 | 방식 | 스크립트 |
|------|------|----------|
| 통합 (권장) | Docker Compose — FE + BE + MySQL | 프로젝트 루트 `deploy.sh` |
| 백엔드만 | JAR / Docker / Cloud Run | `be/deploy.sh` |
| 프론트만 | yarn build / Docker / Cloud Run | `fe/deploy.sh` |

**사전 요구사항**

- 로컬: Docker Desktop(WSL2 연동), `curl`(헬스 체크)
- Cloud Run: `docker`, `gcloud` CLI, GCP 프로젝트 및 Container Registry 권한

---

## 2. 로컬 통합 배포 (Docker Compose)

프로젝트 루트에서 실행한다. `docker-compose.yml`이 MySQL·백엔드·프론트를 한 번에 기동한다.

```bash
# 프로젝트 루트
bash deploy.sh
```

| 명령 | 설명 |
|------|------|
| `bash deploy.sh` | FE + BE + MySQL 빌드·기동 (기본) |
| `bash deploy.sh down` | 컨테이너 중지·삭제 |
| `bash deploy.sh logs` | 로그 스트리밍 |
| `bash deploy.sh ps` | 실행 상태 확인 |
| `bash deploy.sh --help` | 도움말 |

**배포 완료 후 접속 URL**

| 서비스 | URL |
|--------|-----|
| 프론트 | http://localhost:8081 |
| 백엔드 API | http://localhost:8080 |
| Swagger | http://localhost:8080/swagger-ui.html |
| 헬스 체크 | http://localhost:8080/actuator/health |
| MySQL | localhost:3306 (DB: `DBname`) |

**환경 변수 (루트 `deploy.sh`)**

| 변수 | 기본값 | 설명 |
|------|--------|------|
| `VITE_API_HOST` | `http://localhost:8080` | FE Docker 빌드 시 백엔드 API URL |

예: FE가 다른 호스트의 API를 바라보도록 빌드할 때

```bash
VITE_API_HOST=http://192.168.0.10:8080 bash deploy.sh
```

`be/deploy.sh`, `fe/deploy.sh`를 **인자 없이** 실행하면 동일하게 루트 `deploy.sh`가 호출된다.

## 3. 개별 서비스 배포

### 3.1 백엔드 (`be/deploy.sh`)

```bash
cd be
bash deploy.sh build      # Gradle bootJar
bash deploy.sh docker     # Docker 이미지 빌드 (태그: ecoreport-be:local)
bash deploy.sh run        # 단독 컨테이너 (포트 8080)
bash deploy.sh cloudrun   # Cloud Run만 배포
```

| 옵션 | 설명 |
|------|------|
| `--env-file PATH` | 환경 파일 (기본: `.env.docker`) |
| `--tag NAME` | 로컬 이미지 태그 |
| `--network NAME` | `docker run` 시 Docker 네트워크 |

**환경 변수**

| 변수 | 기본값 | 설명 |
|------|--------|------|
| `ENV_FILE` | `.env.docker` | Docker / Cloud Run env |
| `IMAGE_TAG` | `ecoreport-be:local` | 로컬 이미지 태그 |
| `GCP_REGION` | `asia-northeast3` | Cloud Run 리전 |
| `CLOUD_RUN_SERVICE` | `ecoreport-be` | Cloud Run 서비스명 |
| `IMAGE_NAME` | `ecoreport-be` | GCR 이미지 이름 |
| `GCP_PROJECT` | `gcloud config` 값 | GCP 프로젝트 ID |

환경 파일 준비:

```bash
cp be/.env.docker.example be/.env.docker
# SPRING_DATASOURCE_* 등 수정
```

백엔드 Docker 이미지는 `SPRING_PROFILES_ACTIVE=docker`로 기동하며, DB 접속은 `application-docker.yaml` + 환경 변수로 주입한다.

### 3.2 프론트엔드 (`fe/deploy.sh`)

```bash
cd fe
bash deploy.sh build      # yarn build (VITE_API_HOST 필요)
bash deploy.sh docker     # Docker 이미지 빌드
bash deploy.sh run        # 단독 컨테이너 (호스트 8081 → 컨테이너 80)
bash deploy.sh preview    # vite preview (4173)
bash deploy.sh cloudrun   # Cloud Run만 배포
```

| 옵션 | 설명 |
|------|------|
| `--skip-install` | `yarn install` 생략 |
| `--env-file PATH` | 기본: `.env.production` |
| `--api-host URL` | `VITE_API_HOST` 오버라이드 |
| `--tag NAME` | 로컬 이미지 태그 |
| `--port N` | `docker run` 호스트 포트 (기본 8081) |

환경 파일 준비:

```bash
cp fe/.env.production.example fe/.env.production
# VITE_API_HOST=백엔드 URL
```

프론트 Docker 빌드 시 `VITE_API_HOST`가 빌드 인자로 bake-in 된다. Cloud Run 통합 배포 시 백엔드 URL이 자동으로 주입된다.

## 4. GCP Cloud Run 배포

루트에서 BE → FE 순으로 배포한다. BE URL을 조회한 뒤 FE를 해당 URL로 빌드·배포한다.

```bash
export GCP_PROJECT=your-gcp-project-id
# 선택: GCP_REGION=asia-northeast3 BE_SERVICE=ecoreport-be FE_SERVICE=ecoreport-fe

bash deploy.sh cloudrun
```

**흐름**

1. `be/deploy.sh cloudrun` — 이미지 `gcr.io/{project}/ecoreport-be:{git-short-sha}` 빌드·푸시·배포
2. `gcloud run services describe ecoreport-be`로 BE URL 조회
3. `VITE_API_HOST={BE URL}`로 `fe/deploy.sh cloudrun` 실행

**Cloud Run BE 배포 시**

- `--allow-unauthenticated`, 포트 `8080`
- `be/.env.docker`가 있으면 `--env-vars-file`로 주입 (운영 DB URL 등)

**Cloud Run FE 배포 시**

- nginx 정적 서빙, 포트 `80`
- 서비스명 기본: `ecoreport-fe`

> 운영 MySQL은 Compose의 로컬 MySQL이 아닌 **Cloud SQL** 등 외부 DB URL을 `be/.env.docker`에 설정해야 한다. 로컬 Compose MySQL은 개발·데모용이다.

## 5. 파일 구조

```
duyuthon/
├── deploy.sh                 # 통합 배포 (Compose / Cloud Run)
├── docker-compose.yml        # mysql + be + fe
├── be/
│   ├── deploy.sh
│   ├── Dockerfile            # multi-stage: Gradle bootJar → JRE
│   ├── .env.docker.example
│   └── src/main/resources/application-docker.yaml
└── fe/
    ├── deploy.sh
    ├── Dockerfile            # multi-stage: Vite build → nginx
    ├── .env.production.example
    └── nginx/nginx.conf
```

## 6. 트러블슈팅

| 증상 | 확인 |
|------|------|
| `docker compose` 없음 | Docker Desktop 설치 및 WSL 연동 |
| 백엔드 health 타임아웃 | `bash deploy.sh logs`로 BE·MySQL 기동 로그 확인 |
| FE API 호출 실패 | 빌드 시 `VITE_API_HOST`가 실제 BE URL과 일치하는지 확인 (재빌드 필요) |
| Cloud Run `GCP_PROJECT` 오류 | `export GCP_PROJECT=...` 또는 `gcloud config set project` |
| BE Cloud Run DB 연결 실패 | `.env.docker`의 `SPRING_DATASOURCE_URL`이 Cloud SQL 등 reachable한지 확인 |
