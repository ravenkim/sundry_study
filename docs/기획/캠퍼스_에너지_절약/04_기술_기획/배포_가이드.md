# 배포 가이드

EcoReport(FE + BE + MySQL) 로컬 Docker Compose 배포 절차.

---

## 1. 개요

| 구분 | 방식 | 스크립트 |
|------|------|----------|
| 통합 (권장) | Docker Compose — MySQL + BE + FE | 프로젝트 루트 `deploy.sh` |
| 백엔드만 | Docker Compose — MySQL(필요 시) + BE | `be/deploy.sh` |
| 프론트만 | Docker Compose — FE | `fe/deploy.sh` |

루트 `deploy.sh`는 `be/deploy.sh` → `fe/deploy.sh` 순으로 호출하는 래퍼이며, 실제 컨테이너 기동은 모두 프로젝트 루트의 `docker-compose.yml`을 통해 이루어진다.

**사전 요구사항**

- Docker Desktop(WSL2 연동) 또는 Docker Engine + Compose v2
- FE Docker 빌드 전 `fe/.env.production` 준비 (아래 §4 참고)

---

## 2. 로컬 통합 배포

프로젝트 루트에서 실행한다.

```bash
bash deploy.sh
```

**실행 흐름**

1. `be/deploy.sh`
   - `ecoreport-mysql` 컨테이너가 없으면 `docker compose up -d mysql`
   - `docker compose build be` → `docker compose up -d be`
2. `fe/deploy.sh`
   - `docker compose build fe` → `docker compose up -d fe`

**배포 완료 후 접속 URL**

| 서비스 | URL |
|--------|-----|
| 프론트 | http://localhost:8081 |
| 백엔드 API | http://localhost:8080 |
| Swagger | http://localhost:8080/swagger-ui.html |
| 헬스 체크 | http://localhost:8080/actuator/health |
| MySQL | localhost:3306 (DB: `DBname`, 사용자: `your_mysql_user`) |

> 배포 스크립트 완료 메시지에는 서버 IP(`YOUR_DEPLOY_HOST`)가 출력된다. 로컬/WSL에서 접속할 때는 위 `localhost` URL을 사용한다.

---

## 3. 개별 서비스 배포

### 3.1 백엔드 (`be/deploy.sh`)

```bash
bash be/deploy.sh
```

| 동작 | 설명 |
|------|------|
| MySQL 기동 | `ecoreport-mysql`이 없을 때만 `docker compose up -d mysql` |
| BE 빌드·기동 | `docker compose build be` → `docker compose up -d be` |

백엔드는 `SPRING_PROFILES_ACTIVE=docker`로 기동하며, DB 접속 정보는 `docker-compose.yml`의 환경 변수로 주입된다.

### 3.2 프론트엔드 (`fe/deploy.sh`)

```bash
bash fe/deploy.sh
```

| 동작 | 설명 |
|------|------|
| FE 빌드·기동 | `docker compose build fe` → `docker compose up -d fe` |

프론트는 nginx로 정적 파일을 서빙하며, 호스트 `8081` → 컨테이너 `80`으로 매핑된다.

---

## 4. FE API URL 설정 (`VITE_API_HOST`)

FE Docker 이미지 빌드 시 `VITE_API_HOST`가 번들에 포함된다. 배포 전 아래 파일을 준비한다.

```bash
cp fe/.env.production.example fe/.env.production
# VITE_API_HOST를 실제 백엔드 URL로 수정
```

| 환경 | `VITE_API_HOST` 예시 |
|------|----------------------|
| 로컬 Compose | `http://localhost:8080` |
| 원격 서버 | `http://YOUR_DEPLOY_HOST:8080` |

`.env.production`을 수정한 뒤에는 FE 이미지를 **재빌드**해야 반영된다.

```bash
docker compose build fe
docker compose up -d fe
```

---

## 5. Compose 직접 사용

컨테이너 중지·로그 확인 등은 프로젝트 루트에서 `docker compose`를 직접 사용한다.

```bash
docker compose ps              # 실행 상태
docker compose logs -f         # 전체 로그
docker compose logs -f be      # 백엔드만
docker compose down            # 컨테이너 중지·삭제
docker compose down -v         # 볼륨까지 삭제 (MySQL 데이터 초기화)
```

특정 서비스만 재기동:

```bash
docker compose up -d --build be
docker compose up -d --build fe
```

## 6. 파일 구조

```
duyuthon/
├── deploy.sh                 # 통합 배포 래퍼 (be → fe 순 호출)
├── docker-compose.yml        # mysql + be + fe 정의
├── be/
│   ├── deploy.sh             # MySQL(필요 시) + BE Compose 기동
│   ├── Dockerfile            # multi-stage: Gradle bootJar → JRE
│   ├── .env.docker.example   # (참고용) Docker/운영 DB 설정 예시
│   └── src/main/resources/application-docker.yaml
└── fe/
    ├── deploy.sh             # FE Compose 기동
    ├── Dockerfile            # multi-stage: Vite build → nginx
    ├── .env.production.example
    └── nginx/nginx.conf
```

## 7. 트러블슈팅

| 증상 | 확인 |
|------|------|
| `docker compose` 없음 | Docker Desktop 설치 및 WSL 연동 |
| 백엔드 기동 실패 | `docker compose logs be mysql`로 MySQL healthcheck·BE 로그 확인 |
| FE API 호출 실패 | `fe/.env.production`의 `VITE_API_HOST`가 BE URL과 일치하는지 확인 후 FE 재빌드 |
| 포트 충돌 (8080/8081) | 기존 프로세스 또는 컨테이너 점유 여부 확인 (`docker compose ps`) |
| MySQL 데이터 초기화 | `docker compose down -v` 후 재배포 |

## 8. 예정 (미구현)

아래 기능은 문서·기획에 언급되어 있으나 **현재 스크립트에는 포함되지 않았다.**

| 기능 | 예상 명령 (미구현) |
|------|-------------------|
| Cloud Run 배포 | `bash deploy.sh cloudrun` |

| FE yarn 단독 빌드 | `fe/deploy.sh build` |
| 루트 서브커맨드 (`down`, `logs`) | `bash deploy.sh down` |

운영 Cloud Run·Cloud SQL 연동은 [시스템_아키텍처.md](./시스템_아키텍처.md) §6.2 목표 인프라를 참고한다.
