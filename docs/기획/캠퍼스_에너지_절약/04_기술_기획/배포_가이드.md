# 배포 가이드

EcoReport(FE + BE + MySQL) 로컬 Docker Compose 배포 절차.

---

## 1. 개요

| 구분 | 방식 | 스크립트 |
|------|------|----------|
| 통합 (권장) | Docker Compose — MySQL + BE + FE | 프로젝트 루트 `deploy.sh` |
| 백엔드만 | Docker Compose — MySQL(필요 시) + BE | `be/deploy.sh` |
| 프론트만 | Docker Compose — FE | `fe/deploy.sh` |

루트 `deploy.sh`는 `be/deploy.sh` → `fe/deploy.sh` 순으로 호출하는 래퍼이며, 실제 컨테이너 기동은 모두 프로젝트 루트의 `docker-compose.yml`을 통해 이루어진다.

**사전 요구사항**

- Docker Desktop(WSL2 연동) 또는 Docker Engine + Compose v2
- 프로젝트 루트 `.env` 준비 (아래 §4 참고)

---

## 2. 로컬 통합 배포

프로젝트 루트에서 실행한다.

```bash
bash deploy.sh
```

**실행 흐름**

1. `be/deploy.sh`
   - `ecoreport-mysql` 컨테이너가 없으면 `docker compose up -d mysql`
   - `docker compose build be` → `docker compose up -d be`
2. `fe/deploy.sh`
   - `docker compose build fe` → `docker compose up -d fe`

**배포 완료 후 접속 URL**

| 서비스 | URL |
|--------|-----|
| 프론트 | http://localhost:8081 |
| 백엔드 API | http://localhost:8080 |
| Swagger | http://localhost:8080/swagger-ui.html |
| 헬스 체크 | http://localhost:8080/actuator/health |
| MySQL | Docker 내부 `mysql:3306` (DB: `energy_db`) — 상세: [DB_설정_가이드.md](./DB_설정_가이드.md) |

> 배포 스크립트 완료 메시지에는 `DEPLOY_PUBLIC_HOST`가 출력된다. 로컬/WSL에서 접속할 때는 위 `localhost` URL을 사용한다.

## 3. 개별 서비스 배포

### 3.1 백엔드 (`be/deploy.sh`)

```bash
bash be/deploy.sh
```

| 동작 | 설명 |
|------|------|
| MySQL 기동 | `ecoreport-mysql`이 없을 때만 `docker compose up -d mysql` |
| BE 빌드·기동 | `docker compose build be` → `docker compose up -d be` |

백엔드는 `SPRING_PROFILES_ACTIVE=docker`로 기동하며, DB·OAuth·JWT 등은 루트 `.env`(`env_file`)로 주입된다.

### 3.2 프론트엔드 (`fe/deploy.sh`)

```bash
bash fe/deploy.sh
```

| 동작 | 설명 |
|------|------|
| FE 빌드·기동 | `docker compose build fe` → `docker compose up -d fe` |

프론트는 nginx로 정적 파일을 서빙하며, 호스트 `8081` → 컨테이너 `80`으로 매핑된다.

## 4. 서버·로컬 env 설정 (루트 `.env` 하나)

비밀값은 **Git에 올리지 않는다.** 서버에는 아래 **한 파일**만 옮기면 된다.

| 파일 | 서버 | 용도 |
|------|------|------|
| `.env` (프로젝트 루트) | **필수** | Docker·로컬 BE/FE 공통 (유일한 비밀값 파일) |
| `.env.example` | 템플릿 | Git에만 포함, `cp .env.example .env` |

### 4.1 준비

```bash
cp .env.example .env
# .env 에 실제 값 입력 후
bash deploy.sh
```

### 4.2 루트 `.env`에 넣을 변수

| 변수 | 설명 | 서버 예시 |
|------|------|-----------|
| `MYSQL_ROOT_PASSWORD` | MySQL root | 운영용 강한 비밀번호 |
| `MYSQL_DATABASE` | DB 이름 | `energy_db` |
| `MYSQL_USER` / `MYSQL_PASSWORD` | 앱 DB 계정 | Spring과 **동일** 값 |
| `SPRING_DATASOURCE_URL` | BE JDBC (Docker) | `jdbc:mysql://mysql:3306/energy_db?serverTimezone=Asia/Seoul&characterEncoding=UTF-8` |
| `SPRING_DATASOURCE_USERNAME` / `SPRING_DATASOURCE_PASSWORD` | BE DB | `MYSQL_USER` / `MYSQL_PASSWORD`와 **동일** |
| `SERVER_PORT` | BE 호스트 포트 | `8080` |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google OAuth | 콘솔 발급 값 |
| `FRONTEND_URL` | OAuth 성공 후 FE 리다이렉트 | `http://<서버호스트>:8081` |
| `VITE_API_HOST` | FE 빌드 시 API URL (브라우저→BE) | `http://<서버호스트>:8080` |
| `JWT_SECRET` | JWT 서명 (32자 이상) | 랜덤 문자열 |
| `JWT_EXPIRATION_MS` | 토큰 만료(ms) | `86400000` |
| `DEPLOY_PUBLIC_HOST` | (선택) 배포 완료 메시지·`VITE_API_HOST` fallback | 운영 서버 IP 또는 도메인 |

`VITE_API_HOST`를 비우면 `http://${DEPLOY_PUBLIC_HOST}:${SERVER_PORT}`로 FE 빌드 설정이 자동 생성된다.

**맞춰야 할 쌍**

- `FRONTEND_URL` (BE → FE OAuth 리다이렉트) ↔ 서버 FE URL (`:8081`)
- `VITE_API_HOST` (FE → BE API) ↔ 서버 BE URL (`:8080`)

### 4.3 서버로 파일 전송

```bash
scp .env user@<서버호스트>:~/project/duyuthon/.env
```

`VITE_API_HOST` 또는 `FRONTEND_URL` 변경 후에는 `bash fe/deploy.sh`(또는 `bash deploy.sh`)로 FE **재빌드**가 필요하다.

## 5. Compose 직접 사용

컨테이너 중지·로그 확인 등은 프로젝트 루트에서 `docker compose`를 직접 사용한다.

```bash
docker compose ps              # 실행 상태
docker compose logs -f         # 전체 로그
docker compose logs -f be      # 백엔드만
docker compose down            # 컨테이너 중지·삭제
docker compose down -v         # 볼륨까지 삭제 (MySQL 데이터 초기화)
```

특정 서비스만 재기동:

```bash
docker compose up -d --build be
docker compose up -d --build fe
```

```
duyuthon/

├── .env.example              # env 템플릿 (복사 → .env)
├── be/
│   ├── deploy.sh             # MySQL(필요 시) + BE Compose 기동
│   ├── Dockerfile
│   └── src/main/resources/application-docker.yaml
└── fe/
    ├── deploy.sh             # 루트 .env 의 VITE_API_HOST 를 Docker build ARG 로 전달
    ├── Dockerfile
    └── nginx/nginx.conf
```

## 7. 트러블슈팅

| 증상 | 확인 |
|------|------|
| `docker compose` 없음 | Docker Desktop 설치 및 WSL 연동 |
| 백엔드 기동 실패 | `docker compose logs be mysql`로 MySQL healthcheck·BE 로그 확인 |
| FE API 호출 실패 | 루트 `.env`의 `VITE_API_HOST`가 BE URL과 일치하는지 확인 후 `bash fe/deploy.sh`로 FE 재빌드 |
| 포트 충돌 (8080/8081) | 기존 프로세스 또는 컨테이너 점유 여부 확인 (`docker compose ps`) |
| MySQL 데이터 초기화 | `docker compose down -v` 후 재배포 |
| Hibernate validate 실패 | `db/migration/` SQL과 JPA 엔티티 불일치 — [DB_설정_가이드.md](./DB_설정_가이드.md) §8 참고 |
| BE가 호스트 MySQL에 연결 | Docker BE는 `SPRING_DATASOURCE_URL`이 `mysql:3306`인지 확인 (`localhost` 사용 금지) |

## 12. AI Cloud Run 배포

AI FastAPI 서비스는 `ubuntu03` Docker Compose와 **별도**로 GCP Cloud Run에 배포한다. BE `ReportService`가 제보 생성 시 이 서비스를 호출한다.

### 12.1 사전 준비

| 항목 | 설명 |
|------|------|
| GCP 프로젝트 | `duyuthon-496901` (Vertex AI API 활성화) |
| Region | `us-central1` |
| 모델 파일 | `yolov8n.pt`, `models/ac_best.pt` — Git 미포함, 빌드 전 수동 배치 |
| 서비스 계정 | Cloud Run → Vertex AI 호출 권한 |

```bash
cd ai/for_deploy/campus_api
# 가중치 배치 (학습 산출물 또는 팀 공유 파일)
mkdir -p models
cp /path/to/ac_best.pt models/
cp /path/to/yolov8n.pt .
cp Dockerfile.txt Dockerfile
```

### 12.2 로컬 테스트

```bash
cd ai/for_deploy/campus_api
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8080

# 다른 터미널
curl -X POST http://localhost:8080/analyze \
  -F "file=@/path/to/classroom.jpg" \
  -F 'metadata={"reportedAt":"2026-05-24T15:00:00","acCount":1,"fluorescentCount":10,"ledCount":2,"operatingSchedules":[{"dayOfWeek":1,"closed":false,"powerOnTime":"07:00","powerOffTime":"22:00"}]}'
```

### 12.3 Cloud Run 배포 (예시)

```bash
cd ai/for_deploy/campus_api
gcloud run deploy campus-energy-api \
  --source . \
  --region us-central1 \
  --allow-unauthenticated \
  --memory 2Gi \
  --timeout 60
```

배포 후 URL을 BE `ReportService`의 `AI_API_URL`에 설정한다. (현재 하드코딩 — `.env` `AI_API_URL` 분리는 P1)

### 12.4 BE 연동 확인

| 항목 | 값 |
|------|-----|
| BE 호출 URL | `https://campus-energy-api-992786420144.us-central1.run.app/analyze` |
| 요청 필드 | multipart `file` + `metadata` (JSON) |
| DTO | `AiAnalysisResponse` — `result`, `message`, `ac_status`, `light_status`, `reason`, `expected`, `expectedKwh` |

상세 AI 파이프라인: [AI_모델_설계.md](./AI_모델_설계.md) · [ai/README.md](../../../ai/README.md)
