# 탄소 · 문화 확산 · 사업성 — 통합 관점 정리

> 에코리포트(EcoReport)를 **「절전 앱」**이 아니라 **「탄소를 줄이고, 그 행동이 캠퍼스 문화로 퍼지며, 기업·대학·학생 모두 이득을 보는 구조」**로 설명하기 위한 정리 문서.  
> 기술 구현·수치 근거는 기존 문서를 링크로 연결한다.

---

## 1. 한 줄 스토리

```
위치 + 사진 → AI 판별 → 절약·탄소 수치화 → 포인트(기프티콘) → 학생이 반복 사용 → 「꺼야 한다」는 문화 확산
```

| 단계 | 무엇이 일어나는가 | 누가 이득을 보는가 |
|------|-------------------|-------------------|
| **탄소 절감** | 빈 강의실 전등·에어컨 OFF → kWh·CO₂ 절약 | 건물주(전기료), 사회(탄소) |
| **문화 확산** | 학생이 제보·포인트를 경험 → 주변에 말함·모방 | 캠퍼스 전체 |
| **사업성** | 절약분 일부 → 포인트 풀 → 기프티콘 + 플랫폼 수수료 | 운영사·제휴 브랜드 |

> 발표 핵심: **「불을 끄는 행위」** 자체보다, **「학생들이 쓰면서 절전이 당연해지는 문화」**가 지속 가능한 임팩트를 만든다.

## 2. 위치 · 사진 · 사진 정보 (데이터의 출발점)

절약·탄소·포인트는 모두 **「어디서, 언제, 무엇이 켜져 있었는지」**에서 출발한다.

### 2.1 위치 (Where)

| 항목 | 역할 | 구현 |
|------|------|------|
| **LocationNode 트리** | 1·2·3단계 장소(건물→층→강의실) | 관리자 CRUD, LEAF만 제보 대상 |
| **운영 스케줄** | 요일별 `power_on` / `power_off` | 운영 시간 **외**만 제보 가능 |
| **자원 수량** | 형광등·LED·에어컨 개수 | LEAF 메타 → AI metadata |

→ 상세: [장소_관리_모델.md](./04_기술_기획/장소_관리_모델.md)

### 2.2 사진 (What the user captures)

| 항목 | 역할 |
|------|------|
| **원본 이미지** | 조명·에어컨 ON/OFF, 강의실 여부 |
| **촬영 시각** | `reportedAt` — 방치 시간·운영 시간 판단 |
| **(Phase 2) EXIF·GPS** | 옛 사진·캠퍼스 외 제보 차단 |

### 2.3 사진과 함께 AI에 넘기는 metadata (Context)

BE가 AI `/analyze`에 **이미지 + JSON**을 함께 보낸다.

```json
{
  "reportedAt": "2026-05-24T15:00:00",
  "acCount": 1,
  "fluorescentCount": 10,
  "ledCount": 2,
  "operatingSchedules": [
    { "dayOfWeek": 1, "closed": false, "powerOnTime": "07:00", "powerOffTime": "22:00" }
  ]
}
```

**위치·스케줄·자원 수량 없이는** 「얼마나 절약되는지」를 계산할 수 없다.  
사진만으로는 **밝기·ON/OFF**를 보고, metadata로 **시간·전력·단가**를 곱한다.

## 3. AI — 사진을 넣었을 때 **어디를, 어떤 식으로** 보는가

단일 사진 분석이 아니라 **3단 파이프라인**이다.  
→ 상세: [AI_모델_설계.md](./04_기술_기획/AI_모델_설계.md)

```
[사진 + metadata]
    │
    ├─ 1단계 YOLO — 사람·의자·책상 (강의실·빈 방 여부)
    ├─ 2단계 YOLO Custom — 에어컨 위치 크롭
    └─ 3단계 Gemini Vision — 조명·에어컨 ON/OFF + expected(원)
```

### 3.1 「무엇을」 보나

| 관찰 대상 | 판별 방법 | 포인트 적립과의 관계 |
|-----------|-----------|----------------------|
| **사람** | YOLO person count | 1명 이상 → 사용 중 → PASS (적립 없음) |
| **강의실 여부** | chair + desk | 미탐지 → ERROR |
| **조명 상태** | Gemini vision (`light_status`) | ON + 운영 외 → 낭비 |
| **에어컨 상태** | 크롭 + Gemini (`ac_status`) | ON + 운영 외 → 낭비 |
| **운영 시간** | metadata + `reportedAt` | 수업 중이면 PASS |

### 3.2 「어떤 식으로」 보나 — 밝기·촬영 조건

조명 ON/OFF는 **스위치 라벨**이 아니라 **시각적 신호**로 판단한다.

| 신호 | 설명 | 한계 |
|------|------|------|
| **천장·전체 밝기** | 형광·LED 점등 시 실내 luminance 상승 | 창가 역광·어두운 사진 → 판별 불가 ↑ |
| **에어컨 표시등·풍향** | 크롭 영역에서 디스플레이·루버 | 각도·가림 시 미탐 |
| **대비(ON vs OFF)** | 같은 강의실이라도 ON이면 하이라이트·그림자 패턴 변화 | 「켜고 찍기」는 ON만 확인 → 1회 통과 가능 |

**촬영 가이드 (사용자·FE)**  
- 의자·책상이 보이는 **운영 중인 강의실** 공간  
- 천장 조명·에어컨이 **상태가 보이도록** (너무 어둡거나 역광 X)  
- 전체 panorama 불필요 — YOLO 인식 + Gemini 판별에 필요한 구도만

**밝기 이슈 대응**  
- 어두운 사진: 판별 불가 비율 ↑ (목표 15% 이하)  
- 향후: 촬영 전 밝기 힌트 UI, 재촬영 유도  
- 근본: metadata(운영 시간·장소) + YOLO로 **사진 품질과 맥락을 이중 검증**

### 3.3 AI가 **못** 보는 것 (제도로 메우는 구간)

| AI 한계 | 보완 |
|---------|------|
| 「누가 스위치를 켰는가」 | L3 지연 지급·L4 관리자 이의 |
| 촬영 직전 OFF였는지 | 강의실당 1인 1회·소등 확인형 포인트 |
| 악의적 의도 | 경제적 ROI < 전기료 + 제재 |

→ [어뷰징_방지_제도.md](./05_운영_계획/어뷰징_방지_제도.md)

## 4. 얼마나 절약되는가 · 탄소 방어량

### 4.1 제보 1건 (대표 시나리오)

**조건**: 형광등 10개(40W) + 에어컨 1대(1.5kW), 2시간 방치, 단가 130원/kWh

| 지표 | 값 | 공식 |
|------|-----|------|
| 절약 전기 | **3.8 kWh** | Σ(W×수량/1000×h) |
| 절약 금액 | **494원** | kWh × unit_cost |
| 절약 탄소 | **≈ 1.7 kg CO₂** | kWh × 0.4594 |
| 소나무 환산 | **0그루** (1그루 미만) | round(kWh / 20.25) |
| 포인트 | **≈ 89P** | round(494 × 0.18) |

→ 공식·근거: [절약량_환산_공식_및_근거.md](./04_기술_기획/절약량_환산_공식_및_근거.md)

### 4.2 캠퍼스 규모 (발표·기획용 거시 추정)

100개 강의실 기준 **월** 600~1,000 kWh → **275~460 kg CO₂** → 연간 소나무 **50~80그루** 흡수량과 동등 (거시 추정).

### 4.3 「탄소 방어량」 메시지

| 관점 | 메시지 |
|------|--------|
| **방어(Defensive)** | 이미 나가고 있던 전기·탄소를 **제보→소등**으로 막음 |
| **누적** | 제보 건수 × 건당 kWh → 대시보드·마이페이지에 **누적 CO₂·나무** 표시 |
| **플랫폼 순효익** | 서버 전력 ~40.5 kWh/월 vs 제보 1건 3.8 kWh → **월 ~22건**이면 Energy BEP |

→ [서버_전력_및_에너지_손익분기점.md](./04_기술_기획/서버_전력_및_에너지_손익분기점.md) · [06_기대효과_및_성과지표.md](./06_기대효과_및_성과지표.md)

### 4.4 서버·토큰 운영비 vs 전기 절감 — 비교

> **비교 축이 두 가지**다. kWh(에너지)로 보면 **하루 1건** 수준에서 순효익 전환, 현금(원)으로 보면 **변수비(API)는 건당 이득**이지만 **고정비는 건물 계약**으로 회수한다.

#### 4.4.1 플랫폼 월간 운영비 (MVP)

| 구분 | 전력 (kWh/월) | 전기료 (130원/kWh) | 현금 지출 (원/월) | 비고 |
|------|--------------|-------------------|------------------|------|
| 물리 서버 (`ubuntu03`, Docker 24/7) | **40.0** | ~5,200원 | (전기료에 포함) | FE + BE + MySQL |
| Cloud Run + Gemini (1,000건 가정) | **+0.5** | ~65원 | Gemini **~20,000** + GCP **~50,000** | scale-to-zero |
| **합계** | **~40.5** | **~5,265원** | **~70,000원** | §9.2 재무 BEP 기준 |

#### 4.4.2 제보 1건 절감 vs 플랫폼 1건 비용

대표 시나리오(§4.1) + AI 1회 추론 비용:

| 관점 | 제보 1건 **절감** | 플랫폼 1건 **비용** | 배수 |
|------|------------------|---------------------|------|
| **전력** | 3.8 kWh | ~0.0005 kWh | **~7,600×** |
| **전기료** | 494원 | ~0.065원 | **~7,600×** |
| **현금 (API·토큰)** | 494원 | **~20원** | **~25×** |

```
제보 1건 절감:     3.8 kWh  =  494원
플랫폼 1건 비용:   0.0005 kWh ≈ 0.065원 (전력)
                  + ~20원 (Gemini API, 1,000건/월 ÷ 1,000)
                  ≈ 20원 (현금 변수비)
```

**토큰비 특성**: Gemini 1회는 전력 **0.0005 kWh(≈0.065원)** 수준이지만, API **현금 ~20원** — **전력 대비 ~300배** 비중. 다만 **절감 494원 대비 API 20원**이므로 변수비만 보면 **건당 25배** 이득.

실제 소등 반영률 **70%** · 유형 가중평균(**2.55 kWh/건**) 적용 시:

| 지표 | 값 |
|------|-----|
| 유효 절감/건 | **1.79 kWh ≈ 233원** |
| API 대비 | 233 ÷ 20 ≈ **12×** (여전히 플러스) |

#### 4.4.3 월간 시나리오

**Energy BEP — 월 ~22건 (하루 1건)**

```
플랫폼 소비:        40.5 kWh  ≈  5,265원
22건 × 1.79 kWh:   39.4 kWh  ≈  5,120원  → 거의 상쇄
```

**활성 캠퍼스 — 1,000건/월**

| 항목 | 금액 |
|------|------|
| 플랫폼 전기료 | ~5,265원 |
| Gemini + GCP (현금) | ~70,000원 |
| **절감 (70%×가중평균)** | 1,000 × 1.79 × 130 ≈ **233,000원** |
| **순 절감 (전기료 기준)** | **~228,000원/월** |

#### 4.4.4 Energy BEP vs 재무 BEP

| 구분 | BEP 조건 | 에코리포트 기준 | 의미 |
|------|----------|----------------|------|
| **Energy BEP** | 절약 전력 ≥ 플랫폼 전력 | **월 ~22건** | 「절약 플랫폼」**ESG·탄소** 정당성 — 파일럿 즉시 가능 |
| **재무 BEP** | 수수료 ≥ API·클라우드 현금 | **~32개 건물** | **지속 가능한 사업** — 건물주 수수료 모델 필요 |

> Energy BEP(22건)와 재무 BEP(32건물)는 **완전히 다른 축**이다. 「AI가 탄소를 더 쓴다」는 주장은 **전력(kWh) 기준으로는 성립하지 않음** — 1건 절감 ≈ 플랫폼 1건 소비의 **~4,500배**(가중·70% 조치).

→ 상세 산출: [서버_전력_및_에너지_손익분기점.md](./04_기술_기획/서버_전력_및_에너지_손익분기점.md) · [수익_구조.md](./03_비즈니스_모델/수익_구조.md)

## 5. 포인트 · 기프티콘 · SQL (기업적·재무 관점)

포인트는 **「절약의 화폐화」**이자 **「학생 참여의 트리거」**다.  
기업·대학 입장에서는 **절약분 재투자 + 데이터 + 브랜드**로 읽힌다.

### 5.1 돈·포인트 흐름

```
건물주 절약 전기료
    └── 20% 플랫폼 납부
            ├── 10% → 플랫폼 수수료 (운영·AI·인건비)
            └── 90% → 포인트 풀 → 학생 적립 → 기프티콘 교환
```

포인트 산식: **`point = round(절약_원 × 0.18)`**  
(건물주 납부 20% 중 사용자 몫 90% ≈ 절약액의 18%)

→ [수익_구조.md](./03_비즈니스_모델/수익_구조.md)

### 5.2 DB(S SQL) 관점 — 포인트가 어디에 쌓이는가

| 테이블 | 역할 |
|--------|------|
| `member_point_db` | 회원별 **잔액** (`point`, `member_seq` UNIQUE) |
| `report_db` | 제보별 `estimated_point`, `point_awarded`, `estimated_kwh`, `estimated_savings_krw` |
| `reward_db` | 기프티콘 카탈로그 (`point_cost`, category) |
| `gifticon_exchange_db` | 교환 이력 (`point_used`) |

**기업적 해석**

- **대학·건물주**: 절약 전기료의 일부를 **포인트 풀**로 돌려보내면, 직접 현금 인센티브보다 **예산·감사·ESG 보고**에 유리  
- **제휴 브랜드**: 기프티콘 = 마케팅 비용 → 「친환경 캠퍼스」 스폰서십  
- **플랫폼**: SQL로 **제보→절약→포인트→교환** 전 구간 감사·정산 가능 (B2G·B2B 확장 시 필수)

### 5.3 기프티콘이 문화 확산에 기여하는 이유

| 요소 | 효과 |
|------|------|
| **즉시성** | AI 통과 → 포인트 표시 → 「한 번 더 찍을까?」 |
| **가시성** | 친구에게 「이거 쓰면 커피 받음」 → 입소문 |
| **반복** | 500P 커피 등 **눈에 보이는 목표** → 행동 습관화 |

→ **탄소는 추상적**, **기프티콘은 구체적** — 둘을 같은 제보 파이프라인에 묶는 것이 핵심.

## 6. 「불을 껐을 때」가 아니라 — **포인트로 행동을 필수에 가깝게**

### 6.1 문제: 의무가 아니면 안 끈다

| 기존 방식 | 한계 |
|-----------|------|
| 「에너지 절약하세요」 포ster | 행동 변화 미미 |
| 시설팀 순찰 | **인건비**·야간·주말 공백 |
| IoT 자동 소등 | 초기 설비비·유지보수 |

### 6.2 에코리포트 방식: **수십(포인트)에 꼭 하게**

| 장치 | 메커니즘 |
|------|----------|
| **건당 ~50~100P** | 「지나가다 10초」 vs 「커피 한 잔에 가까운 보상」 |
| **강의실당 1회** | 같은 방 반복 수익 불가 → **넓게 퍼지도록** 설계 |
| **누적 대시보드** | 내가 막은 kWh·CO₂ → 게임화·경쟁 |
| **기프티콘 교환** | 목표가 명확 → **「꺼야 포인트가 된다」** 인식 |

**의미**: 「불을 끄는 것」이 도덕이 아니라 **합리적 선택(포인트)** 이 되면, 반복 후 **「원래 꺼야 하는 곳」**으로 문화가 이동한다.

## 7. 문화 확산 — **책임·주체**는 누구인가

### 7.1 책임 구조 (발표용 프레이밍)

```
[시설·건물주]  장소·스케줄·정산 책임  ─┐
[플랫폼]        AI·포인트·어뷰징 감시   ├── 제도적 안전망
[학생]          제보·확산의 1차 주체   ─┘
                      │
                      ▼
              「우리 캠퍼스는 빈 방 불 끈다」
```

| 주체 | 역할 | 「문화」에 기여하는 방식 |
|------|------|---------------------------|
| **학생** | 제보·SNS·동아리 | 또래 설득력 — **확산의 엔진** |
| **건물주** | 장소 데이터·절약분 재투자 | 「학교가 인정한다」는 신호 |
| **플랫폼** | 공정한 포인트·어뷰징 방어 | 신뢰 — 없으면 문화 붕괴 |

**「책임질 사람」**을 한 명으로 두기보다, **학생을 1차 주체**로 두고 나머지는 **제도·데이터·보상**으로 뒷받침하는 구조가 지속 가능하다.

### 7.2 문화 확산 KPI (운영 시)

| 지표 | 의미 |
|------|------|
| MAU / 재제보율 | 습관화 |
| 건물·강의실 커버리지 | 넓이 |
| 제보→실제 소등율 (P1) | 진짜 절약 |
| 입소문·캠페인 UGC | 문화 |

## 8. 제도적 관점 (Institutional)

기술만으로는 「켜고 찍기」 1회를 막을 수 없다 → **제도·경제**로 ROI를 깎는다.

| 레이어 | 내용 | 상태 |
|--------|------|------|
| **L1 사전 차단** | 운영 시간 외만, 강의실 1인 1회, 일일 캡 | 일부 ✅ |
| **L2 AI·촬영** | 사람 없음, 강의실 인식, ON/OFF | ✅ |
| **L3 지급** | 지연 확정, 확인형 50%+50% | P1 ⏳ |
| **L4 사후** | 관리자 이의, 패턴 알림, 계정 제재 | ⏳ |

**대학·공공 연계**  
- 교육부 그린스마트 미래학교, 캠퍼스 ESG 보고  
- 「절약 kWh·CO₂」를 **공식 성과 지표**로 제출 가능한 SQL·API

## 9. 인건비 · 사업성

### 9.1 인건비를 **줄이는** 쪽

| 기존 | 에코리포트 |
|------|------------|
| 시설팀 야간 순찰 | 학생 크라우드소싱 + AI 1차 필터 |
| 강의실별 수동 점검 | 제보 큐·이상 패턴만 관리자 검토 |
| IoT 설치·유지보수 | 스마트폰 + 장소 메타데이터 |

**한계**: 관리자 **이의 처리·소등 확인(P1)**에는 여전히 인력 필요 → AI가 **「전수 조사」를 「표본 검토」**로 축소.

### 9.2 사업성 요약

| 항목 | MVP 기준 |
|------|----------|
| 건물 1개 월 플랫폼 수수료 | ~2,200원 |
| 100개 건물 | ~22만 원/월 |
| 재무 BEP | ~32개 건물 (월 고정비 ~7만 원) |
| Energy BEP | **월 ~22건** 제보 (파일럿 즉시 가능) |
| 건당 API vs 절감 | ~20원 vs ~494원 (**~25×**) — §4.4 |
| 중장기 | 스폰서십, B2G, 익명 에너지 데이터 B2B |

**사업성 + 탄소 + 문화** 삼각형:

```
        사업성 (수수료·스폰서)
           /\
          /  \
         /    \
   탄소 절감 ──── 문화 확산 (MAU·습관)
```

세 축이 **같은 제보·포인트 파이프라인**을 공유할 때만 선순환이 돈다.

## 10. 발표·설득용 — 관점별 한 문장

| 관점 | 한 문장 |
|------|---------|
| **탄소** | 사진 한 장이 **kWh·CO₂·나무**로 환산되어, 막힌 탄소가 숫자로 보인다. |
| **문화** | 포인트와 기프티콘이 **학생의 일상**에 들어오면, 절전이 **캠퍼스 습관**이 된다. |
| **AI** | YOLO로 **빈 강의실**을, Gemini로 **밝기·조명·에어컨**을, metadata로 **얼마나**를 본다. |
| **기업·SQL** | `member_point_db`~`gifticon_exchange_db`까지 **감사 가능한 정산**으로 B2G·ESG에 대응한다. |
| **제도** | 「켜고 찍기」는 **1회 수용 + 다층 방어**로 악용 ROI를 깎는다. |
| **인건비** | IoT·순찰 대신 **크라우드 + AI**로 같은 커버리지를 낮은 고정비로. |
| **행동** | **수십 포인트**가 「그냥 지나치기」보다 **「찍고 포인트」**가 이득이 되게 만든다. |
| **운영비 vs 절감** | 하루 제보 1건이면 **서버 전력 상쇄**; 건당 API ~20원 vs 절감 ~494원 — **AI 변수비는 절감의 1/25**. |
